# ARCHITECTURE — CityBuilder

Версия 7 (фаза 8, после ревью Argon 001–009, 2026-10-25)

## Главные принципы
1. **Данные отдельно от визуала.** Состояние города хранится в `CityGrid` (доступ: `GameState.grid`). 3D-объекты только отображают эти данные и никогда не являются «источником правды».
2. **Симуляция отдельно от рендера.** Логика города считается по тикам (`SimClock`), а не в каждом кадре `_process`.
3. **Связь через сигналы.** Системы общаются через глобальную шину `Events`. Системы симуляции никогда не ищут узлы сцены через `get_node()`.
4. **Типы зданий — данные, а не код.** Каждый тип здания описан в `.tres`-ресурсе (`BuildingData`) со строковым `id`.
5. **Типизированный GDScript.** Везде указываем типы: `var money: int = 0`, `func get_cell(pos: Vector2i) -> int:`.
6. **Не строим заранее.** Системы из поздних фаз не добавляем, пока до них не дошли. Но оставляем для них одну точку входа.

## Автозагрузки (Autoload, глобальные синглтоны)
| Имя | Файл | Назначение |
|---|---|---|
| `Events` | scripts/autoload/events.gd | Только сигналы (шина событий) |
| `GameState` | scripts/autoload/game_state.gd | Деньги, налог, доход и расходы за тик, население, рабочие места, спрос, игровое время `minutes` (и `day` из него), **`grid: CityGrid`** |
| `SaveManager` | scripts/autoload/save_manager.gd | Сохранения: файлы, автосохранение, F5 / F9, новый город |
| `SimClock` | scripts/autoload/sim_clock.gd | Тики симуляции (1 тик = 2 с на ×1 = 1 игровая минута, как в SimCity), часы на экране `time_text()`, скорость (0/1/3/8), пауза — Пробел. `set_speed()` — публичный метод, UI зовёт его напрямую |

`GameState` создаёт сетку при старте: `grid = CityGrid.new(GRID_SIZE)`.

## Модель данных

### CityGrid (`class_name CityGrid extends RefCounted`)
- Размер: `GRID_SIZE = 64`, размер клетки в мире: `CELL_SIZE = 2.0` метра.
- Координаты клетки: `Vector2i(x, y)`. В мире: X → ось X, Y → ось Z, высота = 0.
- Слои (по одному значению на клетку, индекс = `y * GRID_SIZE + x`):
  - `tile_type: PackedByteArray` — EMPTY, ROAD, BUILDING
  - `zone: PackedByteArray` — NONE, RESIDENTIAL, COMMERCIAL, INDUSTRIAL
  - `building_at: PackedInt32Array` — номер экземпляра здания на клетке или -1
- Кэши (чтобы не сканировать всю карту):
  - `buildings: Dictionary[int, BuildingInstance]` — все построенные здания
  - `road_cells: Dictionary[Vector2i, bool]` — все клетки с дорогой
  - `next_building_id: int` — счётчик номеров экземпляров
  - `zoned_empty_cells: Dictionary[Zone, Dictionary]` — по зоне R/C/I словарь `Vector2i → true` пустых клеток с этой зоной. Клетка в кэше ⇔ `tile_type == EMPTY и zone != NONE`. Обновляется **только внутри** `CityGrid`: в `set_zone`, `set_road`, `place_building`, `remove_building`. (Godot не умеет вложенные типизированные словари, поэтому внутренний словарь без типа.)
- Обязательные функции:
  - `grid_to_world(cell: Vector2i) -> Vector3`
  - `world_to_grid(pos: Vector3) -> Vector2i`
  - `is_in_bounds(cell: Vector2i) -> bool`
  - `set_road(cell) -> bool` / `remove_road(cell) -> bool` — **единственное** место изменения дорог; увеличивают `roads_version` (по нему пересчитывается `RoadNetwork`). Возвращают `true`, если клетка изменилась. Сигнал не шлют — это делает инструмент пакетом.
  - `place_building(type_id, cell, orientation, clear_zone = false) -> int` — ставит здание на пустую клетку, возвращает номер экземпляра или −1. `clear_zone` — стереть зону (служебные здания). Правила «какой тип на какой зоне» решает вызывающий (`growth.gd`): `CityGrid` не знает про `BuildingData`.
  - `remove_building(instance_id) -> bool` — клетка снова пустая, зона остаётся.
  - `set_zone(cell: Vector2i, zone_type: Zone) -> bool` — **единственное** место изменения зон (фаза 3). Поштучно, как дороги: цикл и один `cells_changed` — в инструменте. `Zone.NONE` снимает зону.
  - `can_zone(cell, zone_type) -> bool` — те же правила без изменения (для превью инструмента).
  - `find_nearest_road_dir(cell) -> int` — направление (0..3 = N/E/S/W) на ближайшую дорогу в радиусе `ROAD_ACCESS_RANGE` (3) по Манхэттену или −1. Ищет кольцами от расстояния 1. Для дороги по диагонали берётся ось с большим смещением.
  - `find_nearest_road(cell) -> Vector2i` — клетка ближайшей дороги или (−1, −1); на ней построены `find_nearest_road_dir` и `has_road_access`.
  - `has_road_access(cell) -> bool` = `find_nearest_road(cell) != (−1, −1)`.
  - `bulldoze(cell) -> bool` — **единственное** место правил сноса: убирает здание или дорогу. Зону **не трогает** — для снятия зоны отдельное действие. Если снести дом, а зону оставить, при спросе на этом месте вырастет новый (как в SimCity).
- Функции добавляются в той фазе, где нужны: фаза 1 — координаты, фаза 2 — дороги, фаза 3 — зоны, фаза 4 — здания.

### BuildingInstance (`class_name BuildingInstance extends RefCounted`)
Один построенный дом.
- `id: int` — уникальный номер экземпляра
- `type_id: StringName` — тип, например `&"res_small_01"` (ссылка на BuildingData.id)
- `cell: Vector2i` — клетка-основание
- `orientation: int` — направление на дорогу 0/1/2/3 = N/E/S/W (поворот по часовой на 0°/90°/180°/270°, как у кусков дорог). Фасад модели в базовом повороте смотрит на N (−Z).
- `no_road_ticks`, `no_power_ticks`, `no_water_ticks: int` — сколько тиков подряд нет дороги / света / воды (состояние симуляции).
- `powered`, `has_water: bool` — результат последнего распределения.

### BuildingData (`class_name BuildingData extends Resource`)
Описание типа здания (файл `.tres`).
- `id: StringName` — уникальный строковый id. **Никогда не меняется после создания** (на нём держатся сохранения).
- `zone`, `population`, `jobs`, `cost`, `upkeep`, `mesh` (пусто — заглушка-коробка из `placeholder_color` и `placeholder_height`)
- Фаза 6: `power_supply`, `water_supply` (даёт), `power_use`, `water_use` (потребляет), `service` (`BuildingData.Service`: NONE, SCHOOL, HEALTH, FIRE, POLICE), `service_radius`.
- Размер: в MVP всегда 1×1.
- Все типы лежат в `data/buildings/*.tres`. `BuildingCatalog` (статический) загружает их при первом обращении через `ResourceLoader.list_directory` (работает и в экспортированной игре). Пустой или повторный `id` — ошибка, такой тип пропускается. Отсортированный список и списки по зонам собираются один раз при загрузке.
- `upkeep` списывается **только у служебных зданий** (`zone = NONE`): дома содержат себя сами.
- `BuildingCatalog.buildable_types()` — служебные здания (`zone = NONE`), для кнопок UI.

### Дороги
С 2026-11-09 дороги — **граф узлов и кривых** (`RoadGraph`, `CityGrid.roads`), как в Cities: Skylines; подробно — «Дороги как в Cities: Skylines (этап C1)». Клетки `road_cells` / `road_type` — растр графа: на них по-прежнему держатся зоны, рост, трафик и сохранение.
- `CityGrid.get_road_mask(cell) -> int` — 4 бита соседей-дорог: N=1 (−Z), E=2 (+X), S=4 (+Z), W=8 (−X) (полосы зон и доступ; вид от маски больше не зависит).
- `set_road` на клетке с дорогой или зданием ничего не делает и возвращает `false`; дорога стирает зону клетки. Клетки, поставленные `set_road` мимо графа, граф подхватывает сам (`RoadGraph.sync`).
- До 2026-11-09 вид шёл из кусков Kenney по маске соседей (GridMap, `road_meshes.gd` — удалён).

### Зоны
- Зону R/C/I можно поставить только на пустую клетку (не дорога, не здание) **на полосе у дороги** (`in_strip`, с 2026-11-05 — см. «Застройщик по месту»; раньше — дорога в 3 клетках по Манхэттену). Снять зону можно с любой пустой клетки.
- Если дорогу снесли, зона остаётся, но теряет полосу: она рисуется тусклее, и на ней ничего не растёт.
- Снять зону под зданием нельзя: сначала снос (B), потом снятие зоны (4). Так не бывает состояния «дом на клетке без зоны».
- Цвет зоны под зданием остаётся (дом его почти закрывает, а цвет показывает, что это за участок).
- `zone_visualizer.gd` — один `MultiMeshInstance3D`, по экземпляру на клетку (номер = `index_of(cell)`), цвет экземпляра = зона; двор — тон двора (газон, асфальт, площадка); с инструментом зоны — сетка полосы. При `cells_changed` перекрашивает клетки в радиусе `STRIP_DEPTH` от изменённых (доступ соседей мог измениться): одним общим прямоугольником, или отдельным квадратом вокруг каждой клетки, если так выходит меньше клеток (рост в разных углах карты).
- Цвета: R — зелёный, C — синий, I — жёлтый.

### Симуляция (фаза 4)
Порядок одного тика (`simulation.gd`, узел в главной сцене, подписан на `Events.sim_tick`):
1. **Упадок** (`decay.gd`, с 2026-11-01 — см. «Видимый упадок»). У каждого здания без доступа к дороге `no_road_ticks += 1`, с доступом — 0. Через 2 игровых часа без дороги здание пустеет (не исчезает), зона остаётся; брошенные при исправленной причине заселяются снова. До 2026-11-01 здание сносилось через 3 тика.
2. **Рост** (`growth.gd`): для каждой зоны R/C/I со спросом > 0 — одна случайная клетка из `zoned_empty_cells` этой зоны с доступом к дороге; случайный тип здания этой зоны; поворот — `find_nearest_road_dir`. С Р2 — застройщик по месту, с Р5 — несколько попыток за тик в большом городе (см. «Р5 — темп роста»).
3. **Подсчёт** населения и рабочих мест C и I по всем зданиям (пересчёт целиком: просто и не расходится).
4. **Спрос** (`demand.gd`), значения в [−1, 1], рост при > 0:
   - R: `(jobs_c + jobs_i + 7 − population) / 17`
   - I: `(0.7 · population + 5 − jobs_i) / 13`
   - C: `(0.3 · population − jobs_c) / 10`
   - С Р5 буферы и шкалы растут с городом (от ~350 жителей): `max(7, 0.02·N)`, `max(17, 0.05·N)` и т. д. — см. «Р5 — темп роста».
   - Буферы и шкалы — в людях; с 2026-11-01 жителей в доме втрое меньше, и они втрое меньше (было 20 / 50, 15 / 40, 30).
   - К каждому добавляется налоговая поправка `(9 − tax_rate) · 0.08`: налог выше 9 % тормозит рост, ниже — ускоряет.
   - Формулы держат соотношение жители : заводы : магазины ≈ 1 : 0.7 : 0.3. Без налоговой поправки жилой спрос сам вниз не уходит, пока хватает земли всех трёх зон.
5. **Деньги** (`economy.gd`): `money += доход − расходы` (см. «Экономика»).
6. Один `Events.cells_changed` на все изменённые за тик клетки, затем `Events.stats_changed`.

Вне тика (снос на паузе, смена налога, `grid_reset`) `simulation.gd` тоже пересчитывает статистику и спрос и шлёт `stats_changed` — чтобы UI не показывал старые цифры. Флаг «идёт тик» защищает от двойного пересчёта: тик сам шлёт `cells_changed`.

### Экономика (фаза 5)
- **Единственное место изменения денег** — `Economy.spend(amount) -> bool` (строительство) и начисление за тик в тике. Остальные только читают `GameState.money`.
- Старт: 2000 $. Цены за **реально изменённую** клетку: дорога 10 $, зона 5 $, снятие зоны и снос — бесплатно (из долга всегда можно выбраться сносом).
- За час (тик): доход `roundi((население + рабочие места C + I) · tax_rate · 0.045)` (до 2026-11-01 — 0.015 при втрое большем населении: доход с дома прежний), расходы `roundi(клетки дорог · 0.2)` + `upkeep` служебных зданий. Дома не платят содержание.
- `GameState.income` / `expenses` — **прогноз на тик** (в HUD — за игровой час, ×60), пересчитывается вместе со статистикой (и на паузе: стройка, снос, налог). В тике `Economy.apply_tick()` только начисляет `money += income − expenses`.
- Налог: по умолчанию 9 %, от 0 до 20 %, шаг 1 %. UI просит смену через `Events.tax_rate_requested(rate)`, `simulation.gd` проверяет границы и применяет.
- Деньги < 0: игра идёт дальше, сумма в UI красная, банкротства в MVP нет. Платное строительство останавливается там, где кончились деньги; превью заранее показывает только клетки, на которые хватит.
- Все числа — константы в начале `economy.gd`, подбираются игрой.

Числа (сроки `Decay`, буферы и делители спроса) — константы в начале своих скриптов, подбираются игрой.

### Инструменты (build_tool.gd)
- Режимы: NONE, ROAD, BULLDOZE, ZONE_R, ZONE_C, ZONE_I, DEZONE. Клавиши: R — дорога, B — снос, Esc — выключить.
- Дорога (с 2026-11-09): щелчками по точкам — `RoadTool`, см. «Дороги как в Cities: Skylines». Протягивание буквой «Г» по клеткам (`_update_drag` / `_apply`) осталось для тестов и сценариев. Снос: прямоугольник. ПКМ — отмена протягивания.
- Если мышь ушла за карту во время протягивания, конечная клетка прижимается к краю карты.
- Начало протягивания — в `_unhandled_input` (клик по UI не начнёт стройку). Отпускание ЛКМ и отмена ПКМ — в `_input`, чтобы UI не «съел» их и протягивание не залипло.
- Путь и превью пересчитываются только когда меняется конечная клетка.
- Инструмент меняет клетки только через функции `CityGrid` (`set_road`, `bulldoze`, `set_zone`), сам правил не решает.
- Зоны (фаза 3): 1 — жилая R, 2 — коммерческая C, 3 — промышленная I, 4 — снять зону. Протягивание прямоугольником; превью показывает только клетки, которые реально изменятся (`can_zone`).
- У инструмента `class_name BuildTool`, режим — `BuildTool.Mode`. Кнопки UI переключают режим через `Events.tool_requested(mode)`, инструмент сообщает о любой смене (и от клавиш) через `Events.tool_mode_changed(mode)`.
- Курсор клетки скрывается над UI (`gui_get_hovered_control`), но клетка под мышкой продолжает считаться — начатое протягивание не обрывается, если мышь заехала на панель.
- Платные режимы: перед каждой клеткой — `Economy.can_afford`, после изменения — `Economy.spend`.
- Пока идёт протягивание, превью пересчитывается и по `stats_changed` (деньги могли измениться на тике, пока мышь стоит).
- По `grid_reset` инструмент прерывает протягивание; `SimClock` обнуляет накопленное время.
- При отпускании ЛКМ инструмент меняет все клетки и шлёт **один** `cells_changed`.

### Фаза 6 — электричество, вода, службы
Решения по ревью Argon 005 — в `docs/collab/decisions/005-plan-phase-6.md`.

**Цель:** город без света и воды не растёт; службы (школа, поликлиника, пожарные, полиция) по ступеням населения влияют на желание людей жить в городе. Город сам подсказывает, чего не хватает.

#### Служебные здания
- `BuildingData` с `zone = NONE`: ставятся игроком за `cost`, каждый день списывается `upkeep`. Размер 1×1.
- Стартовый набор: ТЭЦ, водокачка, школа, поликлиника, пожарная часть, полиция (`data/buildings/*.tres`). Числа — в таблице decisions/006 (после правки баланса).
- Постройка: пустая клетка с доступом к дороге и хватает денег → `place_building(..., clear_zone = true)` — зона клетки стирается (после сноса службы на её месте не вырастет дом). Рост домов вызывает с `clear_zone = false`. Фасад к дороге.
- **Служебные здания сами не сносятся.** Без дороги, света или воды они просто не работают (не дают мощность и покрытие). Снос — только игроком (`bulldoze`, бесплатно, без возврата денег).

#### Сеть: свет и вода идут по дорогам
- Отдельных ЛЭП и труб нет. `RoadNetwork` (`scripts/simulation/road_network.gd`) делит `road_cells` на связные компоненты (обход в ширину по 4 соседям). Пересчёт ленивый: `CityGrid.roads_version` растёт в `set_road` / `remove_road`; сеть пересчитывается, только если версия изменилась. Объект лежит в `GameState.network` (его читает слой карты).
- Здание подключено к компоненту **ближайшей** дороги: `CityGrid.find_nearest_road(cell) -> Vector2i` (или (−1, −1)). Здание не соединяет два компонента.
- **Распределение** (`scripts/simulation/utilities.gd`), в каждом компоненте отдельно:
  1. Свет: запас = сумма `power_supply` станций компонента. Потребители получают свет по очереди: сначала служебные здания по `id`, затем дома R/C/I по `id`; кому не хватило — без света (следующим, кому хватает, — дают).
  2. Вода: запас = сумма `water_supply` водокачек компонента **со светом**. Очередь та же.
  3. Здание без `power_use` / `water_use` считается обеспеченным. Здание без дороги — без света и воды.
- Результат: флаги `BuildingInstance.powered` / `has_water`, свободный запас по компонентам (для роста), итоги в `GameState`: `power_supply`, `power_use`, `water_supply`, `water_use`, `unpowered_count`, `no_water_count`, компоненты со светом и водой (для слоя карты).
- Распределение и покрытие служб — **часть пересчёта статистики** (`_update_stats`), а не только тика: на паузе после постройки ТЭЦ или дороги всё обновляется сразу.

#### Последствия
- **Рост:** шанс вырасти дому зоны на тике = `min(1, спрос · 0.7)` (было `· 2` до фазы И: город за 2 минуты разрастался до сотен домов; теперь за 2 минуты на ×1 — около 30 домов). Так налог и службы плавно меняют скорость роста, а не только «растёт / не растёт». **С 2026-11-01 свет и вода росту не нужны** (как в SimCity): дом растёт и без них, а над ним висит значок (см. «Значки над зданиями без света и воды»); запас компонента, если хватает, сразу уменьшается. Раньше дом рос, только если у компонента хватало запаса.
- **Заброшенность (только R/C/I):** без дороги — 2 игровых часа (`Decay.NO_ROAD_TICKS`, до 2026-11-01 — 3 тика и снос); без света или воды — 6 игровых часов (`Decay.NO_UTILITY_TICKS` = 360 тиков; было 10, пока дома без света не росли), стройплощадка не считается. Счётчики `no_power_ticks`, `no_water_ticks` в `BuildingInstance`. Здание пустеет, а не сносится (см. «Видимый упадок»); зона остаётся. Дом без света или воды не пустеет от несчастья (`Levels.decline`) — иначе дома, выросшие до первой ТЭЦ, исчезали бы через 20 минут — и не повышается (`Levels.blockers`: «нет света», «нет воды»).
- **Службы** (`scripts/simulation/services.gd`): служба работает, если у здания есть дорога, свет и вода. Покрытие службы = доля жителей, чьи дома в радиусе `service_radius` (по Манхэттену) хотя бы одного работающего здания этой службы.
  - Ступени: школа нужна со 150 жителей, поликлиника — с 250, пожарные — с 350, полиция — с 500.
  - Поправка жилого спроса: `Σ по нужным службам (coverage − 0.5) · 0.25`. Нет службы — −0.125, полное покрытие — +0.125.
- **Деньги:** расходы за тик = дороги + `upkeep` всех служебных зданий (и неработающих тоже).

#### Порядок тика (фаза 6)
1. Заброшенные R/C/I — по флагам последнего пересчёта.
2. Рост — с шансом по спросу и проверкой свободного запаса.
3. `_update_stats()`: сеть (если менялись дороги) → свет и вода всем зданиям, включая новые → население и рабочие места → покрытие служб → спрос → прогноз денег.
4. `Economy.apply_tick()`.
5. Сигналы: один `cells_changed`, затем `stats_changed`.

#### Инструмент и интерфейс
- Режим `BuildTool.Mode.PLACE` + `type_id`. UI просит через `Events.building_place_requested(type_id)`. Клик ставит здание на клетку под мышкой. Превью — одна клетка: цвет режима или красный, если нельзя (занято, нет дороги, нет денег).
- `Events.tool_mode_changed(mode, type_id)` — чтобы UI подсвечивал и кнопку службы.
- Нижняя панель: кнопки служб из `BuildingCatalog.buildable_types()` (`zone = NONE`), с ценой.
- Верхняя панель: «Свет потребление/запас», «Вода потребление/запас»; красным, если кому-то не хватило.
- **Подсказки** (`scripts/ui/hints.gd`): записи по `GameState` («Нет света у 12 зданий», «Нужна школа: покрытие 20 %», «Деньги уходят в минус»). С 2026-11-08 их показывает «Советник» (кнопка в верхней панели, см. «Советник вместо плашки подсказок»); раньше — постоянная плашка слева под верхней панелью.
  - Пустой город ведут первые шаги: «Шаг 1: дорога [R]» → «Шаг 2: ТЭЦ и водокачка» → «Шаг 3: зоны [1] и [3]» — станции раньше зон, чтобы не потратить деньги на зоны.
  - Подсказка кнопки служебного здания: цена, содержание, что даёт и что потребляет, радиус и с какого населения нужна служба.
- Постановка здания (`PLACE`) — только там, где виден курсор клетки: отпускание ЛКМ над панелью UI ничего не ставит (в отличие от протягивания дорог и зон).
- На слоях света и воды станция, которая сейчас не работает (нет дороги; водокачка без света), — красная.
- **Слои карты** (вкладка «Фильтры», `Events.overlay_requested` → `Events.overlay_changed(mode)`): зоны / свет / вода / службы / пробки / цена земли / загрязнение / шум. Рисует тот же `zone_visualizer.gd` на тех же квадратах клеток. Свет: здания со светом — зелёные, без — красные, дороги с запасом — жёлтые. Вода — так же, синим. Службы — клетки в радиусе работающих служб.
- Значки над домами — отложены.

#### Чего в фазе 6 нет
ЛЭП и трубы отдельно от дорог, пожары и преступность как события, стоимость земли, уровни зданий, здания больше 1×1, значки над домами.

### Фаза 7 — сохранение и загрузка
Решения по ревью Argon 007 — в `docs/collab/decisions/007-plan-phase-7.md`.

**Цель:** сколько угодно сохранённых городов, быстрое сохранение, автосохранение, новый город. Загрузка никогда не портит текущую игру: битый файл — город остаётся как был, игрок видит сообщение.

#### Формат файла
- **JSON** в `user://saves/<файл>.city.json`. Не `store_var` / `.tres`: JSON читается глазами и мигрируется, а `.tres` при загрузке может создать скрипт — чужой файл не должен исполнять код.
- Корень:
  ```
  { "format": "citybuilder-save", "version": 1, "saved_at": "2026-10-25T18:00:00",
    "meta":  { "name": "Мой город", "day": 120, "population": 640, "money": 3150 },
    "state": { "money": 3150, "tax_rate": 9, "minutes": 172800, "rank": 3,
               "rng": ["<зерно>", "<положение>"] },
    "grid":  { "size": 64, "next_building_id": 412,
               "roads": "<base64: байт на клетку, 1 — дорога>",
               "zones": "<base64: байт на клетку, CityGrid.Zone>" },
    "buildings": [ { "id": 3, "type": "res_small_01", "x": 10, "y": 18, "o": 2,
                     "nr": 0, "np": 0, "nw": 0, "nh": 0, "ct": 0, "ctt": 0, "ab": 0, "rt": 0 }, ... ] }
  ```
- `meta` — для списка сохранений; имя города живёт внутри файла, имя файла — очищенная версия имени (буквы, цифры, пробел, `_`, `-`; зарезервированные имена Windows получают `_` спереди).
- **Правило совместимости:** незнакомые поля читатель пропускает, отсутствующие берёт по умолчанию. Так позже добавляются размер и стиль здания, уровень, состояние трафика — без поломки старых сохранений.
- `version` новее нашей — отказ; старее — цепочка `_migrate_vN_to_vN1` (в фазе 7 миграций нет, только место).

#### Код
- `scripts/save/city_serializer.gd` (`CitySerializer`, статический, без файлов и сигналов): `to_dict(...)`, `from_dict(data) -> CitySerializer.LoadResult` (`ok`, `error`, `warnings`, `grid`, `money`, `tax_rate`, `day`, `name`). Новый `CityGrid` строится **в стороне**.
  - `JSON.parse_string` отдаёт все числа как `float` — все целые поля явно приводятся к `int`, `type` — к `StringName`.
  - Здания вставляются по возрастанию `id` (на этом порядке держится раздача света и воды); `next_building_id = max(сохранённый, max(id) + 1)`.
- `CityGrid.rebuild_caches()` — из слоёв и `buildings` пересобирает `road_cells`, `tile_type = BUILDING`, `building_at`, `zoned_empty_cells`, `next_building_id`; `roads_version += 1`.
- `scripts/autoload/save_manager.gd` — **четвёртая автозагрузка `SaveManager`**: `save_city(name)`, `load_city(file_id)`, `new_city()`, `list_saves()`, `delete_save(file_id)`; UI зовёт их напрямую, как `SimClock.set_speed`. Папка — `save_dir` (переменная, тесты пишут в свою).
- Загрузка: файл → JSON → `from_dict` → если `ok`: заменить `GameState.grid`, деньги, налог, игровое время, имя → `Events.grid_reset`. Иначе ничего не трогаем → `Events.save_error(message)`.
- **Запись:** `<файл>.tmp`, затем `DirAccess.rename_absolute` поверх старого (в Godot 4.7 на Windows перезаписывает — проверено).
- `Simulation` стоит в сцене **выше** визуализаторов: по `grid_reset` она пересчитывает сеть, свет и воду раньше, чем визуализаторы перерисуются.

#### Проверки при загрузке
- **Отказ:** не JSON, чужой `format`, `version` новее нашей, `size` вне 16..256, длина слоёв ≠ `size²`, байт зоны вне `CityGrid.Zone`, байт дороги не 0/1.
- **Предупреждение и пропуск здания:** неизвестный тип, вне карты, на дороге, второе на клетке, повтор `id`, `orientation` вне 0..3. Зона на клетке дороги и под служебным зданием стирается (как при обычной постройке); `rebuild_caches` тоже снимает зону с клеток дорог.

#### Новый город, автосохранение, клавиши
- `new_city()`: новый `CityGrid`, стартовые деньги, налог по умолчанию, день 1 · 07:00, имя «Новый город» → `grid_reset`. Перед этим окно «Сохранить текущий город?».
- Автосохранение в `autosave` через каждые 2 игровых часа (120 тиков: на ×1 — 4 мин, на ×8 — 30 с) **от последнего автосохранения** (запуск, загрузка и новый город сбрасывают отсчёт — иначе после загрузки оно сработало бы сразу, а при запуске — на первом тике: город начинается в 07:00, а не в минуту 0) и при закрытии окна — **только если город не пустой** (есть дороги или здания), чтобы не затереть прошлое автосохранение пустой картой.
- В списке сохранений автосохранение и быстрое сохранение помечены («Автосохранение: Мой город»), битый файл — «(повреждено)».
- F5 — быстрое сохранение (`quicksave`), F9 — быстрая загрузка.
- Сообщения в HUD на 2–3 с: `Events.save_done(name)`, `load_done(name, warnings)`, `save_error(message)`.

#### Интерфейс
- В верхней панели: «Города» (окно сохранений) и «Новый город».
- Окно сохранений: список (имя, день, жители, деньги, дата), поле имени, «Сохранить», «Загрузить» (и двойной клик), «Удалить» с подтверждением, «Закрыть». Пока окно открыто — пауза и инструмент выключен; клики в мир не проходят.
- Камера не двигается, пока фокус в поле ввода или открыто окно поверх игры (`RTSCamera` опрашивает клавиши каждый кадр напрямую и узнаёт об окнах по `Events.modal_changed`). Окно подтверждения «Новый город» тоже ставит паузу. По `grid_reset` камера прижимается к границам новой карты.
- Esc закрывает окно сохранений с первого нажатия (ловится в `_input`, до поля ввода).
- Имя файла сравнивается со служебными (`autosave`, `quicksave`) и зарезервированными именами Windows **без учёта регистра** (файловая система Windows регистр не различает). `_path` берёт только имя файла (`get_file()`) — выйти за `save_dir` нельзя.
- На слоях карты (V) перерисовка пропускается, пока число экземпляров MultiMesh не совпадает с новой картой: по `grid_reset` `stats_changed` приходит раньше, чем визуализатор пересобран.

#### Чего в фазе 7 нет
Положение камеры в сохранении, ротация автосохранений, сжатие, облачные сохранения, превью-скриншот города.

### Фаза 8 — трафик
Решения по ревью Argon 009 — в `docs/collab/decisions/009-plan-phase-8.md`.

**Цель:** жители ездят из дома на работу по дорогам; где поездок больше, чем дорога выдерживает, — пробка. Долгая дорога до работы снижает жилой спрос. Машинки на дорогах — только визуал.

#### Модель: потоки, а не отдельные машины
- Каждый дом R с дорогой отправляет `workers = population · WORK_SHARE` (0.5) человек на работу. Места работы — **работающие** (свет и вода) здания C и I с дорогой; `jobs_at[клетка дороги]` — сумма их `jobs`.
- **Многоисточниковый Дейкстра** по клеткам дорог от всех мест работы сразу: для каждой клетки — время до работы и «следующая клетка» к ней. Путь дома — по указателям от его ближайшей дороги. Не `AStarGrid2D`: тот ищет путь одной пары точек, а нам нужны пути всех домов.
- **Под-проходы** (`SUB_PASSES = 6`, последовательное распределение): каждый проход развозит 1/6 работников каждого дома, учитывая загрузку, уже набранную прошлыми проходами (в пересчёте на весь поток). Поток делится между дорогой и объездом, «качелей» нет. Расчёт чистый — не зависит от прошлого расчёта, баланс виден сразу после загрузки и после стройки на паузе.
- **Переполненная работа дороже:** стартовая стоимость места работы в проходе = `JOB_OVERLOAD_PENALTY · max(0, приехавшие / места − 1)` (20). Штраф заметно круче штрафа пробки: число мест — жёсткий предел, а пробка — нет (при 6 магазин на 5 мест у выезда забирал треть района — проверка «магазин у выезда»). Один магазин у выезда из района не забирает весь поток — лишние едут дальше, в промзону. В время дороги дома этот штраф не входит.
- **Стоимость клетки** = `_cell_base_cost` (1) `+ JAM_PENALTY · max(0, загрузка − 1)` (3.0); загрузка = нагрузка / `_cell_capacity` (27; до 2026-11-01 — 80 при втрое большем населении). Ёмкость и базовая цена — отдельные функции: будущие проспекты и шоссе меняют только их.
- Очередь Дейкстры — своя двоичная куча прямо в цикле, на локальных `Packed*Array` (в GDScript встроенной нет, а вызовы методов отдельного объекта-кучи стоили дороже самого поиска).
- Пути образуют дерево к местам работы: нагрузка собирается одним проходом с конца порядка Дейкстры — O(дороги) на проход, а не O(дома · длина пути).
- Замеры (Godot 4.7.2, этот ПК): плотный город 64×64 — 14 мс на пересчёт; 256×256 (15 тыс. клеток дорог, 5 тыс. зданий) — около 240 мс.
- `scripts/simulation/traffic.gd` (`class_name Traffic`): `compute(grid) -> Traffic` с полями `load` (по индексу клетки), `home_badness` (по id дома), `jammed_cells`, `average_commute`, `long_commute_share`, `total_workers`, `sample_paths` (выборка путей для машинок). Результат — в `GameState.traffic`.

#### Когда пересчитывать
- Сразу, если сменилась сетка или дороги (`roads_version`) — иначе ездили бы по снесённой улице.
- На тике — раз в `TRAFFIC_PERIOD` (5) тиков.
- Вне тика (стройка, снос на паузе) — если изменились здания (`CityGrid.buildings_version`). Клики по налогу и покраска зон трафик не пересчитывают.

#### Последствия
- Время до работы дома = средняя по проходам сумма стоимостей клеток пути + расстояние от дома до дороги.
- **Тяжесть поездки** дома: `clamp((время − OK_COMMUTE) / (MAX_COMMUTE − OK_COMMUTE), 0, 1)` (25 и 60); нет работы в компоненте — 1.
- **Жилой спрос:** `− TRAFFIC_WEIGHT · long_commute_share` (0.3), где `long_commute_share` — средняя тяжесть по работникам. C и I отдельно не штрафуются: их спрос и так следует за населением.
- Заброшенности из-за трафика нет.

##### Главное меню (`main_menu.gd`, узел `MainMenu` в `main.tscn`)
- `CanvasLayer` выше HUD (layer 10). Отдельной сцены меню нет: меню лежит поверх мира, за ним живой город.
- **Запуск:** грузится самое свежее целое сохранение, камера встаёт над серединой города и медленно облетает его; `Camera3D.h_offset` сдвигает картинку вправо из-под карточки. Нет сохранений — пустая карта.
- **Кнопки:** «Продолжить» (город и день; закрыть меню), «Новый город» (при запуске — сразу; в игре — через подтверждение HUD `request_new_city()`), «Города» (своё окно `SaveDialog`, загрузка закрывает меню), «Выход» (автосохранение, как при закрытии окна).
- **Esc:** в `_shortcut_input` — раньше инструмента. С инструментом в руке Esc снимает инструмент, без него — открывает меню как паузу; в меню (не при запуске) — закрывает. Окна сами ловят Esc в `_input`.
- Пока меню открыто: пауза (скорость до меню вернётся), HUD спрятан, `modal_changed(true)`, клавиши в мир не идут.
- В тестах (сцена добавлена скриптом, `current_scene` не она) меню само не открывается.

### Фаза 9 — вода, стоимость земли, загрязнение, парки, карточка «Инфо»
Решения по ревью Argon 013 — `docs/collab/decisions/013-roadmap-v3.md`.

**Вода.**
- Новый слой `CityGrid.water: PackedByteArray` (0 — суша, 1 — вода). Отдельный слой, а не `Tile.WATER`: дорога-мост лежит поверх воды, и после её сноса вода остаётся.
- На воде нельзя ставить зону и здание; дорога можно — это мост, цена `Economy.BRIDGE_COST` за клетку. Деревьев на воде нет.
- `MapGenerator.add_river(grid, seed)` — река шириной 2–3 клетки поперёк карты, извилистая по шуму. Только при «Новый город» (`SaveManager.new_city`); стартовая сетка `GameState` и тесты — без воды. Старые сохранения — без воды.
- Сохранение: поле `grid.water` (base64), нет поля — суши. Формат остаётся версии 1 (правило совместимости).
- Вид: `WaterVisualizer` — одна плоскость на карту, шейдер рисует воду по маске клеток (маска ×8 с бикубическим сглаживанием — берег плавный, у кромки песок, к середине темнее, рябь и блики). Дорога на воде — модель `road-bridge`, опущенная до асфальта (на прямых), иначе обычный кусок.

**Слои города** (`LandValue`, `GameState.land`; не сохраняются — пересчитываются по городу, как свет и вода):
- `pollution`, `noise`, `land_value` — `PackedByteArray` 0..100.
- Источники — поля `BuildingData`: `pollution` (цеха, ТЭЦ), `noise` (магазины), `land_value` (парки, службы — бонус вокруг). Дороги шумят от загрузки трафика, вода поднимает цену берега.
- Размытие: источники в массив → скользящая сумма радиуса R по X, потом по Y, дважды (треугольное ядро радиуса 2R, пик 1 в источнике). Pollution R=2, noise R=1, бонусы R=2.
- `land_value = BASE + бонусы − 0.7·pollution − 0.4·noise`, обрезка 0..100.
- Источники — только работающие здания: дым и шум — со светом (ТЭЦ — с дорогой); бонус служб — у работающих (`Services.is_active`), парки — всегда.
- Край карты: строки дополняются нулями на 2·R (как бесконечная плоскость) — пик источника у края тот же.
- Доступ к дороге — только от дороги на суше: мост над водой домам доступа не даёт.
- Пересчёт: в `_update_stats`, если сменились `buildings_version` / `roads_version` / трафик: вне тика (стройка, снос на паузе) — сразу; на тике — с Р5 раз в `Simulation.LAND_PERIOD` (5) тиков и не в тик трафика.

**Влияние.**
- Рост R и C: из нескольких случайных кандидатов берётся клетка с наибольшей стоимостью земли; жильё не растёт на клетках с загрязнением ≥ `Growth.MAX_HOME_POLLUTION`.
- Налог с дома и работы × `(0.8 + 0.8·land_value/100)`: обычная земля (25) — ×1, дорогая платит больше — парки окупаются.
- Подсказки: «Дома рядом с заводами: N», «Парк поднимет цену земли».

**Парки** — вкладка «Парки»: сквер, сад, площадь (`BuildingData.park`; модели составляются из деревьев, клумб, дорожек и заборчиков Kenney). Ставятся как службы, у дороги; стоят денег и содержания, дают бонус к стоимости земли.

**Слои карты (V):** «Цена земли», «Загрязнение», «Шум».

**Карточка «Инфо»:** клик по клетке без инструмента в руке → `Events.cell_inspected(cell)` → HUD показывает панель справа: что стоит, жители / работа, свет, вода, стоимость земли, загрязнение, шум. Клик по пустой клетке показывает её цену земли, загрязнение и шум (удобно перед разметкой зон); закрывается крестиком.

### Фаза 10 — плотность, уровни зданий, счастье, звания, стройплощадка
Решения: `docs/collab/decisions/013-roadmap-v3.md` (п. 5, 9) и `014-review-phase-9.md` (п. 5).

**Зоны.** К `CityGrid.Zone` добавлены значения в конце (0..3 не меняются — старые сохранения читаются как есть): `RESIDENTIAL_HIGH = 4` (многоэтажки), `COMMERCIAL_HIGH = 5` (торговые башни), `OFFICE = 6` (офисы). `CityGrid.zone_category(z)` сводит их к R / C / I(+O) для спроса и подсчёта: офисы — «базовые» рабочие места вместе с промзоной. Кэш `zoned_empty_cells` — по всем значениям. Плотность можно перекрасить поверх дома той же категории (R ↔ R высокая): несовпадающий дом со временем перестраивается.

**Уровни 1–3.** `BuildingData.level`; набор типов на каждую зону, цифры (`LevelStats`) — на клетку участка:
| Зона | ур.1 | ур.2 | ур.3 | Модели |
|---|---|---|---|---|
| R | 3 жит. | 4 | 5 | suburban — по объёму модели: меньшие — ур.1 |
| R выс. | 20 | 35 | 50 | commercial m, n и похожие на жильё |
| C | 2 места | 3 | 5 | commercial низкие (кроме моделей школы c и полиции h — решение 011) |
| C выс. | 10 | 15 | 20 | commercial высокие |
| I | 3 | 5 | 8 | industrial по объёму; дым 30/35/40 |
| O | 13 | 20 | 27 | skyscraper a–e; без дыма |

Жители — по семьям, как в Cities: Skylines: частный дом ≈ одна семья (3 человека) на клетку, многоэтажка — десятки квартир; в карточке «Инфо» — «9 (3 семьи)» (`LevelStats.families`, семья — 3 человека). До 2026-11-01 было 10 / 20 / 30 и 60 / 90 / 120 жителей и 5–80 мест — пара домов давала 100–200 жителей. Свет и вода — на клетку, как раньше (ТЭЦ хватает на то же число домов); налог с человека, ёмкость дорог, буферы спроса, машинки и фигурки (`WORKERS_PER_CAR` 1.3, `WORKERS_PER_PERSON` 0.7, на трассе — машина на 40 жителей) пересчитаны под втрое меньшее население. Звания (200 / 600 / 1500 / 4000 / 10000) и службы (школа с 150 жителей…) — прежние: «Посёлок» — примерно через 10–15 домов.
Рост ставит только ур.1. Повышение — замена `type_id` на тип той же зоны следующего уровня (сохранения не меняются); с 2026-11-08 — следующая стадия того же семейства (см. «Дом растёт по стадиям»).

**Счастье** (`Happiness`, 0..100, на здание с жителями или работой; не сохраняется): `50 + службы рядом + (цена земли − 25)·0.5 − загрязнение·0.6 − шум·0.3 − долгая дорога·25 − (налог − 9)·2`, без света или воды — −30. Показ — в карточке «Инфо» (с причинами и тем, что мешает следующему уровню) и в плашке «Жители» (среднее по жителям).

**Повышение уровня** (на тике, до `Levels.UPGRADES_PER_TICK` зданий): спрос зоны > 0, есть свет и вода с запасом под прибавку, цена земли ≥ 30 / 50 и счастье ≥ 45 / 60 для ур.2 / ур.3 (для мест работы — только цена земли). Замер: без парков за 400 дней не повышается ни один дом; со скверами через 6 клеток — около четверти. **Упадок:** счастье < 20 дольше 20 тиков — дом пустеет и стоит брошенным (`Decay.abandon`, до 2026-11-01 — сносился), стройплощадка не пустеет; поле `BuildingInstance.unhappy_ticks` (в сохранении `nh`).

**Стройплощадка:** новое и повышенное здание сначала строится (`construction_ticks`, в сохранении — `ct`/`ctt`; жители и работа считаются сразу). Срок и вид — по размеру здания, см. «Анимация стройки».

**Звания** (`Ranks`): деревня 0 → посёлок 200 → городок 600 → город 1500 → большой город 4000 → мегаполис 10 000. Звание не падает (`GameState.rank`, в сохранении `state.rank`). Награда — деньги; открытия: высокая плотность R и C — «городок», офисы — «город». Плашка звания в HUD, сообщение при новом звании; закрытые карточки зон — серые с подсказкой.

**Инструменты:** режимы `ZONE_R_HIGH`, `ZONE_C_HIGH`, `ZONE_O` (клавиши 5, 6, 7) — в конце `BuildTool.Mode`.

### Разнообразие зданий (слои 1 и 2)
**Слой 1 — свой цвет у каждого дома** (`BuildingPalette`). Модели Kenney красятся одной палитрой `colormap.png` — сетка образцов 8×4 с одинаковой раскладкой у всех наборов. Шейдер по UV узнаёт образец: акценты (крыши, навесы) получают цвет крыши здания, белые и кремовые стены — лёгкий оттенок; окна, двери и тёмные детали не трогаются. Цвет — в `INSTANCE_CUSTOM`: тон и насыщенность крыши, номер оттенка стен, флаг «перекрашивать» (у служб и парков нет — их узнают по виду). Выбор — по району (квадрат 10×10 клеток: тёплый, северный, зелёный, южный набор) и по номеру здания; всегда один и тот же.
- `BuildingVisualizer` — не GridMap, а мультимеш на каждый тип, `use_custom_data`; стройку рисует `ConstructionVisualizer` (у неё здесь только номер куска). Для тестов — `get_cell_item` / `get_used_cells`, как у GridMap.

**Слой 2 — здания из кода** (`ProceduralBuildings`): многоэтажки (6 видов на уровень) и офисы (5 видов на уровень), типы `res_gen_<ур>_<n>`, `off_gen_<ур>_<n>`. Их нет в `data/buildings` — `BuildingCatalog` добавляет их при загрузке; вид — от зерна семейства (тип без уровня, `res_gen_<n>`; с 2026-11-08, раньше — от id): на всех уровнях тот же цвет, рисунок и основание, этажей больше (в сохранениях стабилен). Этажность по уровню, размеры, цвет стен или стекла, рисунок фасада (окна-проёмы, лоджии, ленточные окна, стекло целиком, полосы), уступ у высоких, крыша с будкой и вентиляцией, у офисов — антенна. Окна рисует шейдер фасада по UV в метрах (UV2 — рисунок и высота этажа), без текстур. Цифры по уровням — общие `LevelStats` (их же берёт генератор типов Kenney).

### Дворы заводов (2026-11-08)
Раньше за каждым заводом на 70 % клеток двора стоял контейнер Kenney со случайным поворотом и сдвигом, земля — один «утоптанный» тон: улица заводов превращалась в сплошную контейнерную стоянку (Андрей: «превращается в парковку с контейнерами»). Теперь (`YardVisualizer._works_yard`):
- **Вид двора — один на участок** (`YardVisualizer.works_kind(lot)`, по зерну угла участка — тот же после загрузки; доли `WORKS_SHARES`): склад 18 %, погрузка 17 %, баки 8 %, зелёный 12 %, пустой 45 %. Обставленный двор — меньше чем у половины заводов (Андрей: «не каждый завод должен это иметь»; сначала было склад 35 / погрузка 30 / баки 15 / зелёный 20 %).
  - **Пустой** (`PLAIN`, `YARD_LAWN`): просто трава за цехом — без забора и вещей. Ряды считаются от цеха: первый ряд двора — у здания, задний — у дальней границы участка.
  - **Склад** (`YARD_GRAVEL`): в заднем ряду — два ряда контейнеров вдоль улицы, ярусами (2 яруса — 45 %, 3 — 12 %), в среднем ряду — один ряд через клетку; у цеха — грузовик (25 %).
  - **Погрузка** (`YARD_CONCRETE` — бетон): у цеха — места с разметкой, грузовики Kenney (truck, truck-flat, delivery, delivery-flat; масштаб 0.4) задом к воротам (70 %); сзади — пустой бетон и редкий контейнер.
  - **Баки** (`YARD_TANKS` — тёмный гравий): у задней границы — большой бак через клетку, между ними — малый; баки — цилиндры из кода в стиле силосов на зданиях (белый корпус, оранжевый пояс, крыша-конус; `_tank_mesh`), модели Kenney detail-tank выглядели «тарелками».
  - **Зелёный** (`YARD_LAWN`): газон, ряд деревьев у задней границы и редкие деревья внутри; без забора.
- **Бетонный забор** — только у склада, погрузки и баков (`YardVisualizer.WALLED`; `WALL_HEIGHT = 0.3`, серый бетон; общий край двух дворов — один).
- Контейнеры меньше (`CONTAINER_SCALE` 1.4 → 1.1), чтобы грузовики рядом не казались игрушечными. На тестовой улице (42 завода): обставленный двор — у 17, контейнеров 54 вместо 232 (на 321 клетку двора).
- Тон земли двора `ZoneVisualizer._yard_color` берёт по `works_kind`. Снимок до/после — `docs/collab/visual/industry_yards.png`, проверка — `tests/39_works_yards.gd`.

### Дом растёт по стадиям (2026-11-08)
Раньше большой жилой участок (2×1 … 5×1, 2×2, 3×2) собирался из нескольких домиков Kenney на общем газоне (`CompoundBuildings`: «подворье» 3×2 — пять коттеджей), а уровень менял только модели домиков (+4 % размера) — ур. 3 выглядел той же россыпью. Повышение брало случайный тип того же размера, без связи с прежним домом. Теперь:
- **Одно здание на участок** (`scripts/grid/procedural_houses.gd`, класс `ProceduralHouses`): жилые дома малой плотности строит код. Размеры — как были у составных участков: 1×1, 2×1, 3×1, 2×2, 3×2, 5×1, по `VARIANTS = 4` семейства на размер, у каждого 3 уровня (`res_home_<w>x<d>_<n>_l<ур>`, семейство — без `_l<ур>`; 72 типа, генерация ~25 мс при загрузке каталога). Широкий дом — одно здание на несколько квартир: рядный дом под одной крышей, дверь с козырьком и дорожка на каждую секцию (`UNIT = 1.9` м), между секциями — светлые лопатки. Глубокий — дом с крылом во двор.
- **Стадии семейства:** зерно семейства задаёт стиль — цвет стен, крышу (двускатная или вальмовая; 30 % «современных» — на ур. 3 плоская с парапетом и выходом на крышу), цвет наличников, трубы, сторону пристройки; уровень — размер. Узкий дом (глубина 1): ур. 1 — 1 этаж (у домика 1×1 — 2/3 клетки и двор сбоку), ур. 2 — 2 этажа (у домика — гараж-пристройка в свободную сторону), ур. 3 — 3 этажа во всю ширину с балконами. Глубокий (2×2, 3×2): ур. 1 — корпус в 2 этажа у улицы и сад, ур. 2 — 3 этажа и крыло во двор (Г), ур. 3 — П-образный дом в 4 этажа вокруг дворика. Высота растёт с каждым уровнем у каждого семейства (проверка).
- **Вид:** три поверхности — стены (шейдер фасада `ProceduralBuildings`, новые рисунки 5 «окна дома» — шаг 0.46 м, светлые рамы, на первом этаже без витрин, и 6 «глухая стена» — фронтоны), крыши (`ROOF_SHADER`: тон и насыщенность — из цвета здания `INSTANCE_CUSTOM`, как у домов Kenney в том же районе; полосы черепицы; цвета вершин переводятся из sRGB) и детали (цвет вершин: двери, козырьки, балконы, трубы, цоколь, газон, дорожки). Оттенок стен — тоже из цвета здания: у дома он одинаков на всех уровнях (зависит от номера здания).
- **Повышение — следующая стадия того же дома** (`BuildingCatalog.next_level_types`, его зовёт `Levels`): у типа с семейством (`BuildingData.family`) — следующий уровень того же семейства; у модели без стадий (Kenney, Gemini — у них один вид на все уровни) — типы с семейством того же размера: старый дом перестраивают в больший, дальше он растёт сам; если типов с семействами нет (магазины, заводы) — как раньше, любой тип следующего уровня того же размера. Семейства есть и у башен и офисов `ProceduralBuildings`.

### Дороги как в Cities: Skylines (этап C1, 2026-11-09)
Андрей: «Давай сделаем как в Cities: Skylines, что бы дороги можно было строить как хочешь». Раньше дорога — клетки, протягивание только буквой «Г»; диагональ — «лесенка» из поворотов, проспект той же ширины, что улица, у тупика — странный светлый торец.
- **Граф** (`scripts/grid/road_graph.gd`, `CityGrid.roads`): узлы (`RoadNode`: точка в метрах мира, `Vector2(x, z)`) и отрезки (`Segment`: узлы a, b, управляющая точка квадратичной Безье `ctrl` — у прямой середина, тип). Пересечение двух дорог — узел, обе делятся (`split`, та же кривая — полярная форма `sub_control`). Примыкание к середине дороги делит её (Т-перекрёсток). `version` растёт при каждом изменении — по ней перерисовывается полотно.
- **Растр в клетки** (`RoadGraph.rasterize`): клетки, через которые идёт кривая (шаг 0.3 м), и соседние, куда полотно заходит так, что дом на клетке (полуширина 0.8 м) залез бы на дорогу глубже 0.15 м. Прямая по центрам клеток — ровно ряд клеток (как раньше, та же цена); диагональ и дуга — «толстая лесенка», связная по сторонам. У каждой клетки — t ближайшей точки кривой: `anchor(cell)` — точка дороги в клетке (в клетке узла — сам узел).
- **Постройка:** `plan(grid, from, to, ctrl, type, money)` ничего не меняет — считает куски между пересечениями, новые клетки, цену (как раньше — за клетку, мост дороже) и проверяет: длина ≥ 1.5 м; поворот дуги ≤ 150°; не за краем; угол с дорогами в узле и на пересечении ≥ 30°; кусок между перекрёстками ≥ 1.5 м; дороги «уже нет»; клетки новой дороги не ложатся на чужие и не касаются их — кроме дорог, к которым она примыкает или которые пересекает, и только в 3 клетках от этих мест; служебное здание на пути — нельзя, дом зоны — снесётся (как в C:S). `build(grid, plan)` сносит дома, делит дороги, кладёт куски (`set_road` недостающих клеток, на пересечении тип клетки — больший). Ещё: `remove_segments`, `retype` (+ `retype_cost` — разница цен клеток, вниз бесплатно), `segment_near`, `node_near`, `nearest_on`, `is_locked` (трасса у въезда).
- **Сетка ↔ граф** (`sync`, дёшево, если `roads_version` не менялась): клетки, поставленные мимо графа (старые сохранения, въезд трассы, протягивание по клеткам в тестах), подхватываются прямыми отрезками между центрами клеток — узлы на концах, поворотах, развилках, смене типа и у клеток графа (там дорога графа делится). Клетку отрезка снесли или сменили ей тип мимо графа (инструмент сноса по клеткам) — отрезок разрезается у неё, у остальных кусков та же кривая. Граф только читает сетку: зоны, рост, трафик, полосы и доступ работают по клеткам, как раньше.
- **Перекрёсток со светофором** (`TrafficLights.is_junction` → `RoadGraph.is_junction`) — клетка узла с тремя и более дорогами (не шоссе). Для дорог из клеток это то же, что раньше (≥ 3 соседей-дорог); на «толстой лесенке» диагонали и дуги светофоров нет.
- **Полотно** (`scripts/grid/road_geometry.gd`, `road_visualizer.gd` — `Node3D`, по `MeshInstance3D` на отрезок и на узел; перестраивается только то, у чего изменилась форма): лента вдоль кривой (сечения через 0.4 м по дуге; у прямой — два): асфальт, тротуары с бордюром и внешним бортом, разметка; узел — у каждой дороги обрезка до пересечения краёв соседних дорог + радиус угла 0.35 м, асфальт — многоугольник (`Geometry2D.triangulate_polygon`), углы тротуара — дуги Безье через пересечение краёв, с внешней стороны поворота — дуга вокруг узла; у перекрёстка (≥ 3 дорог) — «зебры» на подходах; тупик — разворотный круг (асфальт на 0.3 м шире), у края карты (въезд трассы) — без круга; по воде — глубокий борт и перила. ### Пешеходы и велосипедисты
- **Выбор способа** (`Traffic.mode_shares`): у каждого дома доли «машина / велосипед / пешком» по логиту `exp(−время / MODE_SPREAD)`. Время на машине — по дорогам с пробками (из Дейкстры); на велосипеде — `длина · 2.2 + 4` (достать и поставить), пешком — `длина · 2.5`; длина пути в клетках — по дереву Дейкстры. Пешком — до 12 клеток, на велосипеде — до 30; если путь идёт по шоссе — только машина. Приезжие с трассы — только на машинах. Веса считаются от самого быстрого способа (`exp(−(время − лучшее) / MODE_SPREAD)`): иначе на долгой поездке в пробке (400+ минут) вес машины во float32 у `Vector3` обнулялся, доли становились 0/0 = NaN, NaN растекался по загрузке дорог, а `TrafficVisualizer` вешал игру (`roundi(NaN)` — самое малое целое; число машинок теперь не меньше нуля).
- **Пробки рассасываются:** на дороги (`road_load`) идёт только доля машин; пешие и велосипедисты сразу добавляются к прибытию на работу. В пробке машина медленнее — часть людей пересаживается; за 6 проходов это сходится к равновесию.
- **Время до работы** для счастья — среднее по долям способов.
- **Итоги:** `Traffic.walkers`, `cyclists`; выборки путей `walk_paths`, `bike_paths` (дома, где доля способа ≥ 12 %). Подсказка «Пробки» в HUD показывает доли.
- **Вид:** `PeopleVisualizer` (наследник `TrafficVisualizer`: переопределяет пути, число, скорость, полосу, замедление в пробке, шаг): узлы `Walkers` (тротуар, 0.84 м от оси) и `Cyclists` (край асфальта, 0.56 м). Модели — Blender (`tools/blender/make_people.py`: прохожий, прохожая, велосипедист) в палитре Kenney; одежда и рама — акцент, свой цвет у каждого по `INSTANCE_CUSTOM`. > **Заменяется** (2026-11-05) разделом «Застройщик по месту» ниже: участки теперь нарезает не разметка, а застройщик при росте. Ниже — как было до переделки.

- **Размер здания задаёт игрок.** Каждая разметка зоны (одно протягивание) нарезается на участки (`CityGrid.Lot`: прямоугольник и сторона фасада) — на каждом вырастает ровно одно здание его размера. Одна клетка — дом 1×1; две вдоль улицы — дом 2×1 на обе клетки; пять — 5×1 и т. д.
- **Нарезка** (`LotPlanner.plan`): фасад — сторона выделения, у которой больше всего дороги (иначе — к ближайшей); вглубь — полосы по 2 клетки (если в зоне есть здания глубиной 2), остаток — 1; вдоль фасада — наименьшим числом кусков из ширин, для которых в зоне есть здания (1, 2, 3, 5, у промзоны, многоэтажек и офисов ещё 7; глубина 2 — 2 и 3), при равенстве — ровнее: 4 → 2 + 2, 6 → 3 + 3, 9 → 3 + 3 + 3.
- **Превью разметки** показывает будущие участки чередующимися оттенками; на слое «Зоны» участки тоже видны (через один — темнее). Карточка «Инфо» на пустом участке пишет его размер.
- **Рост** (`Growth.grow_one`): свободный участок (все клетки пустые, та же зона, связь с трассой) → тип ровно размера участка, поворот — сторона фасада. Клетки зоны без участка (старые сохранения) растут по одной.
- **Не встаёт большой — строится поменьше** (`Growth._fitting_part`): дом во весь участок растёт, только если город его «потянет». Иначе на участке встаёт самый крупный дом, который подходит: сначала у фасада с начала участка, потом дальше вдоль и вглубь. Часть становится своим участком, остаток снова нарезает `LotPlanner`, и на нём потом растут свои дома. Причины:
  - ~~спрос~~ — был предел размера нового дома по спросу (`Growth.max_cells`), но тогда большой участок при слабом спросе дробился на много маленьких домов. Убран (2026-11-01, по просьбе Андрея): размер дома задаёт разметка, спрос — только темп роста. Большой дом может на время увести спрос в минус — его поднимают новые рабочие места;
  - **грязь** — жильё встаёт на чистую часть участка (раньше участок, задетый дымом хоть одной клеткой, пустовал целиком).
- **Жизнь участка:** снос или упадок дома — участок остаётся, вырастет дом того же размера; снятие зоны, дорога поверх, перекраска части участка — участок распадается; перекраска всего участка под домом (смена плотности) — участок остаётся, дом перестраивается того же размера; если у новой зоны нет зданий такого размера — участок распадается на одиночные клетки.
- **Сохранение:** `grid.lots = [[x, y, w, h, сторона], …]`; нет поля — участков нет.

### Застройщик по месту (переделка роста, фазы Р1–Р6 в ROADMAP)
Цель — как в Cities: Skylines и SimCity 4: каждый дом смотрит на свою улицу, размер выбирает город (место, спрос, цена земли), кварталы заполняются целиком.

#### Р1 — полосы зон вдоль дорог (`CityGrid`)
- **Полоса:** у каждой клетки суши — своя улица: ближайшая дорога с доступом (`is_access_road`, не шоссе и не мост) по прямой в одну из 4 сторон, не дальше `STRIP_DEPTH = 4` клеток. Луч останавливается на любой дороге (шоссе загораживает), воде и краю карты. Слои `strip_dir` (сторона на улицу 0..3 = N/E/S/W, `NO_STRIP` = 255 — полосы нет) и `strip_depth` (1 — у самой дороги … 4). При равном расстоянии — меньшая сторона (N, E, S, W): углы кварталов делятся «лесенкой», у каждой улицы фасад на весь квартал.
- **Пересчёт:** производные от дорог, в сохранение не идут. `set_road` / `remove_road` пересчитывают крест ±4 клетки вокруг изменённой клетки (`_update_strips_near`), `rebuild_caches` — всю карту (`rebuild_strips`).
- **Разметка:** `can_zone` для R/C/I/… требует полосу (`in_strip`), а не «дорогу в 3 клетках по Манхэттену» (`has_road_access` остаётся для служб). Снять зону — где угодно. Зона, оставшаяся без полосы (снесли дорогу, старые сохранения), рисуется тусклой и не растёт.
- **Вид:** пока выбран инструмент зоны, свободные клетки полос подсвечены (`ZoneVisualizer`, белёсые квадраты, глубже — бледнее) — видно, куда можно красить, как сетка зон в C:S.

#### Р2 — застройщик (`Growth.grow_one` переписан, `LotPlanner` больше не нужен для разметки)
- **Разметка не режет участки.** Покраска только ставит зону. Участок появляется вместе с домом.
- **Где строить:** фасадные клетки — свободные (нет здания и участка) клетки зоны с `strip_depth == 1`, чья улица связана с трассой. Из них берётся `VALUE_SAMPLES` случайных, по каждой строится план, побеждает лучший (цена земли; промзоне всё равно).
- **План для фасадной клетки:** ряд свободных фасадных клеток той же зоны и той же улицы вдоль дороги (до 7 в каждую сторону); у каждой клетки ряда — глубина колонки вглубь (свободные клетки той же зоны и полосы подряд, до 4). Ширина дома — из ширин типов зоны: желаемая = база зоны + спрос + цена земли ± случай; окно ряда, содержащее клетку, оценивается: близость к желаемой ширине, «сироты» (клетки глубже самой мелкой колонки окна — их потом не достать), огрызки ряда короче самой узкой ширины зоны.
- **Участок** = окно × самая мелкая глубина его колонок (до 4), сторона — к улице. **Дом** — тип ширины окна и глубины не больше участка (глубже — охотнее), у самой улицы; остальное — **двор** (клетки участка без здания). Сначала `place_building`, потом `add_lot`.
- **Жизнь участка:** снос, распад стройплощадки, перестройка (`redevelop`) — участок распадается вместе с домом (`remove_building`), двор снова свободен, застройщик решит заново. Дорога, служба или другая зона на клетке двора — участок распадается (дом остаётся без двора). Повышение уровня — тип того же размера, участок тот же.
- **Двор:** клетки двора — зона, `Tile.EMPTY`, `lot_at` = участок. В `zoned_empty_cells` (свободная земля) только клетки без участка. Бульдозер по двору сносит дом участка; клик «Инфо» по двору — карточка дома.
- **Цифры:** жители и места — по зданию (тип), двор — ноль. Плотность на клетку зоны падает (жильё ~ вдвое) — баланс в Р5.
- **Старые сохранения:** дома и их участки — как были; участки без дома отбрасываются при загрузке (`rebuild_caches`); старые дома не у улицы стоят, пока не снесут. Участок в сохранении — до 7 × 4 клеток.
- **Вид дворов** (`scripts/grid/yard_visualizer.gd`, узел `YardVisualizer`): тон земли двора рисует `ZoneVisualizer` (`YARD_LAWN`, `YARD_COURT`, `YARD_PARKING`, `YARD_GRAVEL`), предметы — мультимеши: жильё — белый штакетник по краям двора (общий край — один забор), деревья и клумбы Kenney; многоэтажки — деревья; магазины и офисы — разметка парковки (3 места на клетку) и машины Kenney (30 % мест); промзона — двор одного вида на участок, у части — за бетонным забором (с 2026-11-08, см. «Дворы заводов»; раньше — контейнеры Kenney вразнобой на 70 % клеток). Расстановка детерминированная по клетке; пересборка при смене `lots_version` или `buildings_version`.
- **Аудит** (кварталы 9×9, 600 тиков): 92 дома, спиной к улице — 0 (было 64 из 93); свободной размеченной земли 61 кл. из 424 (сироты на углах и ещё не застроенное). Много брошенных домов от шума у магазинов и заводов — это Р3.
- Проверка — `tests/33_developer.gd` (снимок `tests/out/developer.png`).

#### Р3 — желанность места (`Growth.place_score`, `why_not`)
- **Оценка плана** = желанность места по клеткам фасада − штраф плана · `VALUE_PER_PENALTY`; общее за один рост (службы, дома, трафик) — `place_context`. Без `land` (проверки) желанности нет.
- **Жильё** (R, R высокая): «счастье места» — как `Happiness.factors`, но без налога, дороги до работы, света и воды (`home_factors`: службы рядом, цена земли, загрязнение, шум). Ниже `MIN_HOME_MOOD = 30` — не строят (между порогом упадка 20 и заселения брошенных 35: новый дом не пустеет сразу); в дыму от 40 — тоже. Из подходящих — где счастье выше.
- **Магазины:** ½ цены земли + `CUSTOMER_WEIGHT` · √жителей в 6 клетках (до 150) + поток машин по улице у фасада · 12 − дым · 0.3.
- **Промзона:** дешёвая земля ((50 − цена) · 0.3) − `INDUSTRY_HOME_WEIGHT` · √жителей в 4 клетках — заводы уходят от домов.
- **Офисы:** цена земли + службы рядом · 4 − дым · 0.5.
- **Шум улиц вдвое тише** (`LandValue.ROAD_NOISE` 6 → 3, `TRAFFIC_NOISE` 20 → 10): теперь у дороги стоит каждый дом, а у соседней с улицей клетки шум вдвое больше клетки дороги (линия источников). Дом у загруженной улицы — «место» ~37, у загруженного проспекта — ниже 30.
- **«Почему здесь не строят»** (`Growth.why_not`, карточка «Инфо» пустой клетки зоны): «далеко от дороги», «нет выхода на улицу: между клеткой и дорогой занято», «улица не связана с трассой», «нет спроса», «загрязнение 70 — жильё не строят от 40», «место на 26 из 30: шум −24»; у жилья — строка «Место для жилья 42 (строят от 30)». Подсказка «Жильё не строят на шумных местах: N кл.».
- **Аудит** (те же кварталы, 600 тиков): брошенных 0 (было 20 — от шума), жителей 249 (было 183), участков 77; пустует жильё в дыму от ТЭЦ и промзона без спроса. Снимок — `docs/collab/visual/desirability_blocks.png`.
- Проверка — `tests/34_desirability.gd`.

#### Р4 — укрупнение (`scripts/simulation/consolidation.gd`, класс `Consolidation`)
- **Что:** как в SimCity 4 — когда земля дорожает, застройщик сносит 1–3 соседних участка одной улицы и застраивает их заново домами поглубже: дом растёт вглубь двора (2×1 → 2×2), соседние участки сливаются (три домика 1×1 на участках 1×4 → дом 3×2), широкий дом без глубокого варианта уступает место двум глубоким (ряд коттеджей 5×1 → 3×2 и 2×2: в каталоге жилья глубокие только ширины 2 и 3). Новые дома — стройплощадки (`Levels.start_construction`), пока строятся — в них никого.
- **Кто может** (`blockers`, пусто — готов): растущий дом зоны с участком, не брошен, не стройка, зона всех клеток участка — как у дома; спрос категории > 0; цена земли под домом ≥ `MIN_VALUE = 40` (между уровнями 2 и 3), у промзоны вместо цены — спрос ≥ `INDUSTRY_DEMAND = 0.5`; есть свет и вода; дом стоит готовым ≥ `MIN_AGE_TICKS = 120` тиков (2 игровых часа; `BuildingInstance.age_ticks` растёт в `Levels.tick_construction`, сохраняется полем `age`, в старых сохранениях — 0).
- **Планы** (`find_plans`): от каждого готового участка — он сам, он + следующий, он + два следующих по улице (`_next_lot`: соседний участок той же стороны на улицу и той же полосы — совпадает поперёк улицы, та же глубина; та же зона). Новые дома (`_plan`): уровень — меньший из сносимых, глубина ≤ глубины участка; ширины — раскладка всей ширины участков с наибольшим числом жителей и мест (жители в каталоге пропорциональны площади, поэтому выигрывает глубина), из равных — меньше домов; вместе ≥ `MIN_GAIN = 1.5` от снесённых. Несколько участков — только если домов станет меньше (2×1 + 3×1 не перестраиваются вместе в 2×2 + 3×2 — каждый растёт вглубь сам).
- **Тик** (`step`, в `Simulation` после повышений): с шансом `CHANCE = 0.2` — одно укрупнение, план случайный. `apply`: запас света и воды компонента на прибавку (`_shortage`, как у повышения), снос домов (`remove_building` — участки распадаются), новые дома по порядку вдоль улицы, каждому — свой участок на всю глубину (`Growth.build_lot`, общий с ростом: дом у улицы, двор позади).
- **«Инфо» дома:** строка «Укрупнение» (`status`): что мешает («цена земли 31 из 40», «дом новый — ещё 1 ч 30 мин», «нет спроса»), «не хватает света на дом 3×2», «скоро: дом вглубь двора, 2×2», «скоро: с соседями (3 уч.) в дом 3×2», «скоро: вместо него дома 3×2 и 2×2 — глубже» или «ждёт соседей: на свой участок дома больше нет».
- **Аудит:** кварталы 9×9 с парками у улиц, 1500 тиков — 7 укрупнений, жителей 305 против 237 без укрупнения, брошенных 0; дальше рост упирается в спрос (жилью не хватает работы). Улица с парками (`docs/collab/visual/consolidation_street.png`): за 600 тиков 6 укрупнений, рядов 5×1 из 7 осталось 2, домов 2×2 и 3×2 — 20 вместо 9, жителей города 421 вместо 288.
- Проверка — `tests/35_consolidation.gd`.

#### Р5 — темп роста (`simulation.gd`, `demand.gd`)
- **Попытки:** у каждой зоны за тик `Simulation.growth_tries(население)` попыток роста: 1 + по одной на каждые `GROWTH_POP_PER_TRY = 250` жителей, не больше `MAX_GROWTH_TRIES = 5`. Шанс попытки — прежний `спрос · 0.7`. Неудача места (`grow_one` вернул `NO_CELL`) — попытки зоны кончаются.
- **Запас спроса:** у категории (R, C, I) на тик запас = спрос × шкала (`Demand.scale_of` — сколько жителей или мест не хватает); каждая стройка вычитает жителей и места нового дома, при запасе ≤ 0 новых попыток нет. Первая попытка — всегда: малый город (до 250 жителей) растёт, как раньше, с тем же ходом случайности. Стройки входят в население и места сразу (спрос следующего тика их видит) — перерасти спрос нельзя.
- **Шкалы и буферы спроса растут с городом** (`BUFFER_SHARE = 0.02`, `SCALE_SHARE = 0.05` от «своей» базы: жители; заводы — 0.7 жителей; магазины — 0.3): R `(места + max(7, 0.02·N) − N) / max(17, 0.05·N)`, I — так же от `0.7·N`, C — шкала `max(10, 0.015·N)`. До ~350 жителей — прежние числа. Раньше в городе на 2000 буфер 7 давал спрос ~0.07 (рост стоял), а дом на 40 жителей перекидывал спрос на 2 (рывки); теперь равновесный спрос ~0.4 в любом городе, а тот же дом сдвигает его на 0.4.
- **Общий context попыток:** `Growth.place_context` (службы, жители, трафик) считается один раз на тик и передаётся в `grow_one`; новый дом с жителями дописывается в его `homes` — следующая попытка видит покупателей.
- **Подсказка** (`Hints`): спрос категории ≥ `LAND_HINT_DEMAND = 0.3`, а свободной клетки зоны у улицы, связанной с трассой (`Hints.has_free_frontage`), нет — «Жилью / Магазинам / Заводам нужна земля: спрос N%, … — разметьте ещё [1/2/3]». Раньше рост в таком случае стоял молча.
- **Быстрее тик:** `Happiness.factors` принимает список служб `null` = «посчитать здесь», а пустой список — «служб нет» (раньше пустой список считался «не передали», и город без служб перебирал все здания на каждый дом: 54 мс на тик при 250 домах, теперь 3). Слои земли на тике — раз в `LAND_PERIOD = 5` и не в тик трафика (`Simulation._land_due`; вне тика и для новой сетки — сразу): оба счёта по ~20 мс.
- **Замер** (`tests/out/r5_measure.gd`, карта 64×64, кварталы 9×9 на ~2000 клеток зон, службы, свет и вода): до Р5 — 343 жителя к тику 150 и 804 к тику 300, затем рост встал (кончилась земля магазинов, спрос C +100% — молча); после — 465 и 940. С магазинами в достатке: 746 к тику 150, 1193 к тику 195 (вся жилая земля застроена, спрос R +100% и подсказка «Жилью нужна земля»), без переполнения и пустующих из-за роста. Без служб (та же карта, 3000 тиков): 798 жителей вместо 708, тик — 40 мс на 344 здания вместо 86 мс на 301; со службами на 430 зданий — 46 мс.
- **Плотность и звания — без изменений.** Замер: на клетку участка жильё даёт 1.75 жителя (на клетку дома — 3.1, дом занимает 57 % участка), магазины 1.13 места, заводы 1.9. Полкарты зон на уровне 1 — ~1200 жителей («Городок», 600 — многоэтажки открываются вовремя), «Город» (1500) — с уровнями или многоэтажками, «Большой город» (4000) и «Мегаполис» (10 000) — только с многоэтажками (20–50 жителей на клетку). Цифры `LevelStats` под дворы не поднимали: дворы — цена красоты, плотность возвращают укрупнение (Р4) и уровни.
- Проверка — `tests/36_growth_pace.gd`.

### Игровое время
- Как в SimCity 2013: на часах идут минуты, игровой час на ×1 — около 2 реальных минут (так говорят EA и замеры игроков; официальной цифры нет), сутки — 48 минут. `GameTime` (scripts/simulation/game_time.gd): 24 часа в сутках, новый город начинается в 07:00.
- **1 тик = 1 игровая минута** (`GameTime.TICK_MINUTES`) = 2 с на ×1. Скорости как черепаха / лама / гепард: ×1 — час за 2 мин, ×3 — за 40 с, ×8 — за 15 с (тик раз в 0.25 с; тик в городе на 100 зданий — 8–11 мс). Тиков в реальную секунду на ×1 — столько же, сколько было, поэтому город растёт с прежней скоростью; медленнее идут только часы.
- `GameState.minutes` — минуты с полуночи первых суток; `GameState.day` считается из них (только чтение). Текст часов — `SimClock.time_text()`, длина часа на скорости — `SimClock.seconds_per_hour()` (подсказки кнопок скорости и часов).
- Деньги в игре считаются за тик, а в интерфейсе — **за игровой час** (`GameTime.per_hour`, ×60), как бюджет «§/час» в SimCity 2013: баланс в HUD «$/ч», содержание дорог и служб. Стройплощадка — в игровых минутах.
- HUD: «Город · День 3» и часы отдельной надписью постоянной ширины (цифры у шрифта разной ширины — соседние плашки дрожали бы); обновляются каждый кадр, только когда текст изменился.
- Сохранение: `state.minutes`; в `meta.day` — номер суток для списка сохранений. Старые сохранения: `state.hours` (тик был часом) — то же время, `state.day` (тик был днём) — тот же день, 07:00.

### Анимация стройки (как в Cities: Skylines)
- **Срок по размеру** (`Levels.construction_ticks_for`): 3 тика + 2.6 · √(жители + места). Домик 1×1 — 8 игровых минут (16 с на ×1), ряд 3×1 — 11, многоэтажка 2×2 ур.3 — 40, многоэтажка 7×1 ур.3 — 52. `Levels.start_construction` ставит `construction_ticks` и `construction_total` (рост и повышение уровня). Карточка «Инфо»: «Стройка 40 %, ещё 5 мин».
- **Вид** (`scripts/grid/construction_visualizer.gd`, узел `ConstructionVisualizer` в `main.tscn`), по доле готовности `p` (с долей текущего тика `SimClock.tick_progress` — плавно между тиками, на паузе замирает):
  - всю стройку: земля во весь участок и забор Kenney вдоль улицы с воротами-шлагбаумом, конусами и фонарём (`BuildingMeshes.site_mesh`, кэш на тип; забор — перед лесами, на тротуаре);
  - `p` 0–0.12 — заливают фундамент (бетонная плита под домом);
  - 0.12–0.9 — дом растёт снизу вверх: свой меш с материалами `BuildingPalette.construction_material` — тот же шейдер палитры (цвета дома те же, через `instance uniform building_custom`), но выше `cut_height` ничего нет, изнутри и у верхней кромки — бетон; вокруг — леса ярусами по 0.5 м до текущей высоты;
  - 0.9–1 — дом готов, леса разбирают сверху вниз; в конце площадка исчезает, дом рисует `BuildingVisualizer`.
- **Краны:** у зданий от 2.4 м (частные дома строят в одних лесах); два — у широких (от 4 клеток) и больших (клетки × высота от 20). Мачта внутри дома у задних углов, на 1.4 м выше крыши, из секций по 1 м; стрела — 0.75 большей стороны дома (2–7 м). Стрела качается, тележка ездит, груз на крюке опускается к текущему ярусу.
- **Модели** — Blender (`tools/blender/make_construction.py` → `assets/models/blender/construction/`: модуль лесов, секция мачты, поворотная часть, стрела, трос, крюк с пачкой балок; превью `docs/collab/visual/construction_preview.png`). Леса и краны — мультимеши на все площадки; площадка, фундамент и растущий дом — узлы на каждую стройку (их немного).
- `BuildingMeshes.mesh_for` — один меш на тип (кэш): его делят `BuildingVisualizer`, стройка и значки.

|---|---|---|---|
| Свет | 200 кВт | 450 кВт | 1 000 кВт |
| Цена / содержание за час | $100 / $120 | $220 / $240 | $250 / $360 |
| Дым / шум | 0 / 8 | 0 / 4 | 70 / 20 |

  Ветряк за киловатт дороже ТЭЦ, зато без дыма — рядом можно жить. Модели — Argon (`tools/blender/make_services_and_wind.py` → `assets/models/blender/services/`): трёхлопастной (HAWT) и вертикально-осевой (VAWT, Дарье — Горлова).
- **Ротор крутится** (`scripts/grid/rotor_visualizer.gd`, узел `RotorVisualizer` в `main.tscn`): модель здания — основание без ротора (`services/parts/wind_*_base`), ротор — отдельная модель (`BuildingData.rotor`), один мультимеш на тип. Ротор ставится на ось `rotor_pivot` (в координатах модели: обычный — `(0, 3.38, 0.44)`, к улице; вертикальный — `(0, 1.04, 0)`) тем же трансформом, каким модель вписана в участок (`BuildingMeshes.model_placement` = `ModelLoader.fitted_placement`, кэш на тип), и крутится вокруг `rotor_axis` со скоростью `rotor_speed` (оборот за 4 и 3 с). Время идёт только при идущей игре; начальный угол — по id здания (соседние не в такт); у ветряка без дороги (не даёт свет) ротор стоит; на стройке ротора нет. Обновление — по `cells_changed` и `grid_reset`.
- Иконки карточек — `tools/blender/make_ui_icons.py` (полная модель с молнией, как у ТЭЦ); одну-две иконки можно перерисовать отдельно: `ICONS_ONLY="wind_turbine_01,wind_turbine_02"`.
- Подсказки и шкала знают о ветряках: «Шаг 2: поставьте у дороги ТЭЦ или ветряк…», «нужна ещё ТЭЦ или ветряк»; в подсказке шкалы — что даёт каждая станция (из каталога). Снимок: `docs/collab/visual/wind_turbines.png`.

### Видимый упадок (как в SimCity и Cities: Skylines)
- **Было:** дом без дороги исчезал через 3 тика (6 секунд при ×1) — случайно снёс кусок улицы, и квартал пропал; несчастный дом и дом без света — тоже исчезали.
- **Стало** (`scripts/simulation/decay.gd`, `Decay.step` — первым на тике): здание пустеет, а не исчезает. Сроки: без дороги — 2 игровых часа (`NO_ROAD_TICKS`, 4 минуты при ×1), без света или воды — 6 часов (`NO_UTILITY_TICKS`), несчастье — `Levels.DECLINE_TICKS` (20 тиков, `Levels.decline` зовёт `Decay.abandon`). Пока срок идёт — значок «нет дороги» над крышей, подсказка «Без дороги N зд.» и строка «Опустеет через 1 ч 59 мин — нет дороги» в «Инфо». Стройплощадка без дороги к сроку просто исчезает; служебные здания не пустеют.
- **Брошенное здание** (`BuildingInstance.abandoned`, в сохранении `ab`): жителей и работы нет — не считается в населении, рабочих местах, налоговой базе, трафике, покрытии служб и счастье; свет и воду не берёт (`Utilities.distribute` ставит ему `powered` / `has_water` как «хватило бы запаса»); не дымит и не шумит; цену земли вокруг снижает на `LandValue.ABANDONED_PENALTY` (8 на здание, по клеткам поровну, размытие как у бонусов: у брошенного 1×1 своя клетка −8 из 25, соседи −5…6; ряд брошенных тянет сильнее — упадок расползается). Не повышается. Участок занят — новый дом там не вырастет.
- **Вид:** `BuildingVisualizer` рисует брошенные здания в своём слое на тип (создаётся при первом таком доме) с `material_overlay` упадка (`DECAY_SHADER`, `blend_mul`): тот же дом темнее и бурее, вертикальные потёки на стенах, пятна на крыше, грязь у земли — поверх любых материалов (Kenney, пак Gemini, башни из кода). Над крышей — тёмная булавка с досками крест-накрест.
- **Что делать игроку:** снести бульдозером (бесплатно, зона остаётся) или исправить причину. Брошенное здание заселяется снова, если `RECOVER_TICKS` (1 игровой час) подряд нет помех (`Decay.recover_blockers`): есть дорога и путь до трассы, хватает света и воды, счастье будущих жильцов ≥ 35 (`RECOVER_HAPPINESS`, выше порога упадка 20 — дом не пустеет и не заселяется по кругу), спрос его зоны > 0. Счётчик — `recover_ticks` (в сохранении `rt`). Въезд — через короткую стройку-ремонт (`Levels.start_construction`). В «Инфо» брошенного: «Состояние — заброшено», «Не въезжают: нет дороги, счастье 14 из 35» или «Въедут через 40 мин», «Снести — бульдозер [B]». Подсказка «Заброшено N зд.».
- Проверка — `tests/32_decay.gd` (снимок `tests/out/decay.png`).

### Значки над зданиями: свет, вода, дорога, брошено
- Как в SimCity: дома, магазины и заводы растут и без света с водой, а над зданием, которому не хватило, висит значок — красная булавка с жёлтой молнией (нет света) или голубой каплей (нет воды). Нет ни того, ни другого — два значка рядом. С 2026-11-01 ещё два (Decay): красная булавка с перечёркнутой дорогой — нет дороги, скоро опустеет (вместо значков света и воды: они идут по дороге), и тёмная с досками крест-накрест — здание брошено (только он). Провели свет и воду — значок пропадает при ближайшем пересчёте. У служб без света и воды — тоже.
- **Модели** — Blender (`tools/blender/make_badges.py` → `assets/models/blender/badges/badge_power.glb`, `badge_water.glb`, `badge_road.glb`, `badge_abandoned.glb`; только некоторые — `BADGES_ONLY="badge_road,…"`; превью `docs/collab/visual/badges_preview.png`): булавка в белой окантовке (видна на любой крыше), в ней белый круг с объёмным символом; острие в (0, 0, 0), высота 1 м, лицевая сторона −Y Blender.
- **Показ** (`scripts/grid/badge_visualizer.gd`, узел `BadgeVisualizer` в `main.tscn`): по мультимешу на значок, обновляется по `stats_changed` — после каждого пересчёта света и воды. Значок 1.4 м, острие на 0.3 м выше крыши (`BuildingMeshes.height_of` — верх меша типа, кэш). Шейдер поворачивает значок к камере и покачивает его (фаза — по id здания, `INSTANCE_CUSTOM.r`); сдвиг вбок в плоскости экрана — `INSTANCE_CUSTOM.g`: `(g − 0.5) · SPREAD` метров (один значок — по центру, два — по 0.66 м в стороны). Цвета частей — из материалов модели. Без теней; стройплощадкам значок не нужен.

## Отображение
- **Слой «Трафик»** (пятый по V): дороги от зелёного через жёлтый к красному (загрузка ≥ 1); дома, которым далеко до работы, — оранжево-красные по тяжести.
- **Машинки** (`scripts/grid/traffic_visualizer.gd`, один `MultiMeshInstance3D`): число ∝ поездкам (4 работника на машину), не больше 300. Едут по правой полосе; внутри клетки — квадратичная кривая Безье от середины входного ребра к середине выходного (на прямой — прямая, на повороте — дуга; с 2026-11-09 точки клеток — `RoadGraph.anchor`, на кривой дороге — точка полотна); в тупике разворачиваются на встречную полосу. Медленнее на загруженных клетках, стоят на паузе. Машинка доезжает свой рейс «дом → работа → дом» и только потом берёт новый путь из выборки; сразу — если путь сломан (снесли дорогу) или новый город.
- **HUD:** «Пробки N · до работы M»; подсказки «Пробки на N кл.: постройте объезд», «Жителям далеко до работы: N %».

### Визуальная фаза В1 — модели и красивая картинка
Сделано по просьбе Андрея до ревью Argon 011 (запрос остаётся — как ревью уже написанного кода). Снимки «до / после» — `docs/collab/visual/before_close.png`, `after_close.png`, `after_wide.png`.

**Как устроено в итоге:**
- `ModelLoader` (`scripts/grid/model_loader.gd`) собирает из GLB один `ArrayMesh` (все части, трансформы запекаются в вершины, материалы с палитрой Kenney сохраняются) и считает габариты; `placement()` ставит модель основанием в центр клетки с поворотом и масштабом.
- `BuildingData`: `model`, `model_scale`, `model_turns` (2 = фасад Kenney +Z → наш −Z), `sign_color`. `BuildingMeshes.mesh_for()`: модель → `mesh` → заглушка. Масштаб = `model_scale`, но основание не больше `FOOTPRINT` (1.8 м). Масштабы наборов: дома 1.35, магазины 1.9, цеха 0.95.
- 52 новых типа (`res_house_b…u`, `com_shop_b…n`, `ind_factory_b…t`) генерирует `tools/generate_building_types.gd`; старые id получили модели (`…-a`), службы — модели и вывески. Цифры внутри зоны одинаковые — баланс фаз 4–8 не тронут.
- Дороги: куски Kenney, ×2 по X/Z (асфальт тонкий, 0..0.02). Поворот каждого куска — **по геометрии** (`RoadMeshes.native_mask`: вершины у середины края только на открытых сторонах), проверка — рукава всех кусков совпадают с `BASE_MASKS`. Без моделей — прежние заглушки.
- Машины: 8 моделей Car Kit, `MultiMeshInstance3D` на модель (дочерние узлы `TrafficVisualizer`), масштаб 0.28; без моделей — коробочки.
- Земля — шейдер (трава из `FastNoiseLite`, за краем карты темнее, поле 60 м вокруг); сетка видна только с выбранным инструментом; зоны прозрачнее; тёплое солнце под углом, мягкие тени, SSAO, лёгкая дымка.
- Замер (витрина: 104 здания, ~100 машин): кадр 5.4 мс, 790 вызовов отрисовки, 1.16 млн треугольников — больше всего дают машины; если понадобится — упрощённые модели машин.

**Правки по ревью Argon 011** (`docs/collab/decisions/011-plan-visual-v1.md`, снимки `v1_round2_*`):
- `ModelLoader.fitted()` — модель загружается один раз; части с одним материалом склеиваются в одну поверхность (`SurfaceTool.append_from`): у машины 1 поверхность вместо 5–7.
- Масштабы наборов сближены: дома 1.1, магазины 1.4, цеха 1.0.
- `BuildingData.grows` (по умолчанию true): модели служб и многоэтажки (`com_shop_c/f/g/h/l/m/n`, `ind_factory_l`) сами не растут, но остаются в каталоге; рост берёт `BuildingCatalog.growable_types()`.
- Службы: школа — Kenney с вывеской; вывеска ставится на реальную крышу в точке крепления (`BuildingMeshes._roof_height`). Поликлиника, пожарная часть и полиция с 2026-11-01 — модели Argon со своими эмблемами, без вывески (см. «Службы из пака Argon»).
- Дороги: повороты — таблица `RoadMeshes.MODEL_TURNS = [3, 1, 2, 3, 0]`; `native_mask` — только в тесте.
- Машины: 10 моделей с весами (`rand_weighted`), полиция ≈ 3 %; без теней.
- Свет: рассеянный 0.5, тон Filmic (`tonemap_white` 1.4 — ACES на проверке выбелил картинку), `shadow_bias` 0.03, `shadow_normal_bias` 1.2, тени в 2 ступени (PSSM 2). Зоны: высота 0.006, под построенным домом прозрачность 0.08. Край карты в шейдере земли — мягкий (`smoothstep`, 3 м).
- **Деревья** (`scripts/grid/tree_visualizer.gd`): `tree-large` / `tree-small`, по `MultiMeshInstance3D` на модель; рощи по `FastNoiseLite` (частота 0.13) на свободных клетках (нет дороги, здания, зоны) и лесом на 30 клеток вокруг карты; масштаб 1.6–2.4, до 4 на клетку, не больше 7000; расстановка детерминированная (`hash(cell)`); перестройка — только если по `cells_changed` у клетки изменилась свобода.
- Замер витрины: кадр 5.4 мс, вызовов отрисовки 790 → ~300; треугольников ~1.27 млн (вместе с деревьями).

**Изначальный план (для истории):**

**Цель:** вместо коробок-заглушек — настоящие low-poly модели в одном стиле, ближе к уютному виду ориентира CityRT. Логика симуляции не меняется.

#### Ассеты
- Пять наборов **Kenney** (лицензия CC0 — можно всё, указание автора не обязательно): `assets/models/kenney/{suburban, commercial, industrial, roads, cars}/` — GLB-модели, `Textures/colormap.png` рядом (одна общая палитра-текстура на набор), `License.txt`. Всего ~18 МБ.
- Размеры (замер в Godot): дороги — плитки ровно 1×1; дома (suburban) — 1.3–1.8 в ширину; магазины (commercial) — ~0.9; цеха (industrial) — до 2.1; машины — 2.5–3.5 в длину.
- Ориентация (контактные листы в `docs/collab/visual/`): здания и машины смотрят «лицом» на **+Z**, у нас фасад — **−Z** → поворот 180°. Дорожные куски: прямая идёт по X (у нас базовая — по Z), T закрыт с −Z, тупик открыт на +X.

#### Здания: модель в типе здания
- `BuildingData`: новые поля `model: PackedScene` (GLB), `model_scale: float` (0 — подобрать самому), `model_turns: int` (поворот в шагах по 90°, по умолчанию 2 = 180°). Старые `mesh` и заглушка-коробка остаются запасным вариантом.
- `BuildingMeshes` при сборке MeshLibrary: из GLB собирает **один** `ArrayMesh` (все `MeshInstance3D` с их трансформами), масштаб — `model_scale` или автоматически «вписать в 1.8 м по большей стороне основания», модель ставится в центр клетки на землю (`set_item_mesh_transform`).
- **Разнообразие:** по `.tres` на модель — жилых 21 (suburban a–u), магазинов 14 (commercial a–n), цехов ~12 (выбранные industrial). Цифры (жители, места, свет, вода) — пока одинаковые внутри зоны, рост и так берёт случайный тип зоны. Небоскрёбы и большие цеха — позже, для ступеней роста и уровней зданий.
- `.tres` генерируются одним скриптом-инструментом (`tools/generate_building_types.gd`, запуск из редактора / `--script`), чтобы не писать 47 файлов руками; id — `res_<модель>`, `com_<модель>`, `ind_<модель>`. Старые id (`res_small_01` …) **остаются** — на них держатся сохранения фазы 7.

#### Служебные здания
- ТЭЦ — `industrial/chimney-large` (градирня), водокачка — `industrial/water-tower`.
- Школа, поликлиника, пожарная часть, полиция — подходящие модели из наборов (подбор по листам) + **вывеска**: цветная табличка над крышей, собранная кодом (школа — жёлтая, поликлиника — белая с красным, пожарные — красная, полиция — синяя). Отдельный набор моделей служб — позже.

#### Дороги
- `RoadMeshes` берёт куски из `roads`: END = `road-end`, STRAIGHT = `road-straight`, CORNER = `road-bend`, T = `road-intersection`, CROSS = `road-crossroad`; масштаб ×2 (клетка 2 м). Базовый поворот каждого куска (чтобы его «рукава» совпали с `BASE_MASKS`) вычисляется **автоматически** при сборке: по геометрии асфальта у середины каждого края плитки — а не подбирается на глаз. Тест проверяет все 15 масок.
- Высоты: асфальт Kenney — 0..0.02 над землёй; зоны (0.015) остаются под ним, слои карты (0.04), превью (0.05), курсор (0.06) — над ним.
- Процедурные куски остаются запасным вариантом, если модели не загрузились.

#### Машинки
- 6–8 моделей (`sedan`, `taxi`, `suv`, `van`, `truck`, `delivery`, `hatchback-sports`, изредка `police`) — **по одному `MultiMeshInstance3D` на модель**, у каждой машинки — номер модели. Цвет — из текстуры модели (не `use_colors`). Масштаб ~0.28 (седан ≈ 0.7 м — помещается в полосу), поворот 180°. Число и логика движения — как в фазе 8.
- Позже: скорая / пожарная / полицейская машина возле работающей службы.

#### Земля, свет, небо
- **Земля:** шейдер вместо однотонного зелёного — трава с мягкими пятнами (встроенный `FastNoiseLite` → `NoiseTexture2D`, без загрузок), чуть темнее за пределами карты.
- **Сетка** видна только когда выбран инструмент (в обычном режиме — чистая картинка, как в CityRT).
- **Свет:** тёплое солнце, мягкие тени, `SSAO`, тон `ACES`/`Filmic`, небо светлее и теплее, лёгкий туман вдали. Всё — в `main.tscn` / окружении.

#### Проверки
- Тест: все типы зданий собираются в MeshLibrary, у каждой модели основание ≤ 1.9 м и она стоит на земле; все 15 масок дорог дают куски с рукавами ровно по маске; машины — по полосам, как в фазе 8.
- Снимки «до / после» одного и того же города.
- Производительность: GridMap с ~50 кусками и 6–8 MultiMesh машин — замер кадра на плотном 64×64.

#### Чего в В1 нет
День и ночь (свет в окнах), деревья и декор на пустых участках, здания больше 1×1, стили районов, уровни зданий (небоскрёбы) — следующие шаги ориентира.

## Проверки и детерминизм
- **Проверки** — в `tests/`: каждая `NN_тема.gd` — сценарий `extends SceneTree`, запускается отдельным Godot (`--path . --script res://tests/NN_тема.gd`, с рендером — некоторые снимают экран) и печатает в конце `ALL OK` или `FAIL: …`. Все разом: `bash tests/run.sh`, выборочно: `bash tests/run.sh 14 25`; путь к Godot — переменная `GODOT`.
- Каждая проверка ставит `SaveManager.save_dir = "res://tests/out/test_saves/"` — настоящие сохранения в `user://saves/` не трогаются. Снимки и логи — тоже в `tests/out/` (там `.gdignore`: редактор не импортирует).
- В `--script` имена классов, зависящих от автозагрузок (`Economy`, `CitySerializer`, `Growth`, `UtilityMeter`…), не видны при компиляции — проверки берут их через `load()` и держат экземпляры без типа.
- **Детерминизм:** вся случайность симуляции (рост, выбор дома, повышения) — `GameState.rng`. Новый город берёт зерно карты, загрузка — зерно и положение из `state.rng` (строками: в JSON числа — float и теряют 64 бита), старое сохранение без поля — случайное. Тот же город и те же действия на тех же тиках дают тот же город, и после загрузки он растёт так же, как без неё (стройплощадки тоже сохраняются: `ct`, `ctt`). Случайность вида (деревья, машинки, башни) — своя и на город не влияет. Проверка — `tests/31_determinism.gd`.

## Сигналы (Events)
- `cells_changed(cells: Array[Vector2i])` — пакетный. Инструмент сначала меняет все клетки, затем шлёт **один** сигнал на всю операцию.
- `grid_reset()` — сетка полностью заменена (загрузка/новая игра), визуал перестраивается целиком.
- `sim_tick()` — шлёт `SimClock`, один раз за тик симуляции.
- `stats_changed()` — шлёт `simulation.gd` после тика и после изменений вне тика: в `GameState` обновлены деньги, население, рабочие места, спрос.
- `tool_requested(mode: int)` — UI просит сменить инструмент.
- `tool_mode_changed(mode: int, type_id: StringName)` — инструмент сменил режим (от кнопки или клавиши); `type_id` — для режима PLACE.
- `building_place_requested(type_id: StringName)` — UI просит режим постановки служебного здания.
- `overlay_requested(mode: int)` — просьба показать слой (вкладка «Фильтры», выбор станции или службы); `ZoneVisualizer` меняет слой.
- `overlay_changed(mode: int)` — сменился слой карты.
- `save_done(name: String)`, `load_done(name: String, warnings: int)`, `save_error(message: String)` — для сообщений в HUD.
- `modal_changed(open: bool)` — открылось или закрылось окно поверх игры (камера перестаёт слушать клавиши).
- `menu_requested` — кнопка «Меню» в HUD просит открыть главное меню.
- `speed_changed(speed: int)` — шлёт `SimClock.set_speed`.
- `tax_rate_requested(rate: int)` — UI просит сменить налог.

### Интерфейс (`scenes/ui/hud.tscn`, `hud.gd`)
- `CanvasLayer` → корневой `Control` на весь экран с `mouse_filter = IGNORE` (клики мимо панелей идут в мир).
- **Тема** (`ui_theme.gd`, фаза И) собирается кодом и вешается на корневой `Control` и окна: светлые «бумажные» панели, скругления, тёплый акцент. Вариации: `Title`, `Caption` (надписи), `Chip` (плашка показателя), `Small`, `Tab`, `Card` (кнопки). У каждой категории свой цвет (`UiTheme.CATEGORY_COLORS`): полоска снизу у вкладки и карточки, заливка у выбранной.
- Верхняя панель: город, день и часы, плашки — деньги и баланс за час (подсказка: доход и содержание отдельно), жители, рабочие места, спрос R/C/I, налог (−/+, кнопки гаснут на границах); скорость (Пауза / ×1 / ×3 / ×8, в подсказке — длина игрового часа); «Города», «Новый город»; за часами — значок «Советник» со счётчиком проблем (2026-11-08). Плашки переносятся на вторую строку (`HFlowContainer`).
- Полоска спроса (`demand_bar.gd`) растёт **от центра**: вправо цветом зоны при спросе > 0, влево тусклым при < 0, посередине риска нуля. Пустая полоска = рост стоит.
- Нижняя панель — **вкладки** из таблицы `TABS`: «Дороги», «Зоны», «Свет и вода» (здания, дающие свет или воду), «Службы». Над вкладками — ряд карточек открытой вкладки (название, цена, клавиша). Повторный клик по вкладке сворачивает ряд. Выбор инструмента клавишей сам открывает его вкладку. «Снос» и «Фильтры [V]» — рядом с вкладками, всегда видны.
- **Фильтры** (`scripts/ui/filter_panel.gd`, как карты данных SimCity и инфо-виды Cities: Skylines) — вкладка нижней панели, открывается и клавишей V. Свет, вода и пробки переехали сюда из верхней панели, чтобы она не была перегружена.
  - Карточки: Свет, Вода, Пробки, Службы, Цена земли, Загрязнение, Шум — под названием короткая цифра («загрузка 93%» станций, клетки с пробкой, домов в грязи…), красным — если плохо. Клик — слой на карте, повторный клик — обратно к зонам.
  - Справа — легенда выбранного фильтра: цифры по городу (без света N зд., время до работы, покрытие каждой службы, средняя цена земли…) и что значат цвета.
  - Фильтр виден, пока открыта его вкладка: другая вкладка или инструмент дорог и зон — снова зоны (как в C:S). Выбор станции — сам слой света или воды, службы — покрытие, парка — цена земли (как в SimCity). Снос слой не сбрасывает.
- **Шкалы света и воды** (`scripts/ui/utility_meter.gd`, как в инфо-видах Cities: Skylines) — во вкладке «Свет и вода» справа от станций (обе) и в легенде фильтров «Свет» / «Вода» (своя):
  - заголовок с иконкой и «4 170 / 5 000 кВт» (вода — «315 / 400 м³/сут»); заливка — потребление города, бегунок (риска с треугольником) — сколько дают станции; шкала на 15 % длиннее большего числа, чтобы бегунок не лип к краю;
  - цвет: зелёный — с запасом, оранжевый — от 85 % мощности («пора ставить ещё одну»), красный — не хватает («Не хватает 2 170 кВт — нужна ещё ТЭЦ») или станций нет; внизу — запас и сколько зданий без ресурса (бывает и при запасе: дом в другой сети дорог);
  - единицы — `Utilities.KW_PER_UNIT` (10 кВт: домик 1×1 — 10 кВт, ТЭЦ — 1 000 кВт) и `M3_PER_UNIT` (1 м³ в сутки, водокачка — 100 м³); `Utilities.power_text`, `water_text`, `digits` (тысячи через неразрывный пробел). Те же единицы — в карточке «Инфо» («Свет: 10 кВт, есть», «Даёт свет: 1 000 кВт») и в подсказке станции. Симуляция по-прежнему считает в целых единицах.
  - Снимки: `docs/collab/visual/utility_meters.png` (хватает), `utility_meters_shortage.png` (не хватает).
- У всех кнопок `focus_mode = NONE`: иначе Пробел нажимал бы последнюю нажатую кнопку вместо паузы.
- UI не меняет состояние напрямую: только сигналы `Events` и `SimClock.set_speed`.
- Остальные сигналы добавляются сюда по мере появления.

## Отображение
- Дороги и здания: `GridMap` + `MeshLibrary` (в 4.7 есть встроенный редактор MeshLibrary). MeshLibrary зданий собирается кодом из `BuildingCatalog` (номер куска = порядок типов по `id`).
- Если зданий станет очень много — переход на `MultiMeshInstance3D`.
- Зоны: полупрозрачная раскраска клеток.

## Отложенные решения
- Здания больше 1×1: экземпляр уже хранит основание, добавится поле размера.
- **Трафик на больших картах:** на 256×256 пересчёт ~240 мс — заметная заминка раз в 5 тиков. Когда появятся карты больше 64×64 — переносить расчёт в фоновый поток (`WorkerThreadPool`): снять копию слоёв и зданий, считать в потоке, применить результат на главном.
- **Загрузка сохранений (фаза 7):** не через `set_zone`/`set_road` — в сохранении бывают зоны без доступа к дороге и зоны под домами. Загрузка пишет слои и здания напрямую, затем `CityGrid.rebuild_caches()` пересобирает `road_cells`, `zoned_empty_cells`, `buildings`/`building_at`, `next_building_id`; затем `grid_reset`.
  - **Сохраняется:** `GameState.money`, `tax_rate`, `day`; `CityGrid.size`, дороги, слой `zone`, `next_building_id`; здания: `id`, `type_id`, `cell`, `orientation`, `no_road_ticks`, `no_power_ticks`, `no_water_ticks`.
  - **Не сохраняется (пересчитывается):** `roads_version`, кэши `CityGrid`, `powered` / `has_water`, `GameState.network`, `utilities`, `service_coverage`, население, рабочие места, спрос, доход и расходы — всё это даёт `grid_reset` → `Simulation._refresh_stats()`.
- **Поиск пути** решён в фазе 8 многоисточниковым Дейкстрой (`traffic.gd`); `AStarGrid2D` понадобится только для маршрутов «из точки в точку» (например, режим прогулки из ориентира CityRT).
