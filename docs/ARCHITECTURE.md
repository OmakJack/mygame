# ARCHITECTURE — CityBuilder

Версия 6 (фаза 7, после ревью Argon 001–007, 2026-10-25)

## Главные принципы
1. **Данные отдельно от визуала.** Состояние города хранится в `CityGrid` (доступ: `GameState.grid`). 3D-объекты только отображают эти данные и никогда не являются «источником правды».
2. **Симуляция отдельно от рендера.** Логика города считается по тикам (`SimClock`), а не в каждом кадре `_process`.
3. **Связь через сигналы.** Системы общаются через глобальную шину `Events`. Системы симуляции никогда не ищут узлы сцены через `get_node()`.
4. **Типы зданий — данные, а не код.** Каждый тип здания описан в `.tres`-ресурсе (`BuildingData`) со строковым `id`.
5. **Типизированный GDScript.** Везде указываем типы: `var money: int = 0`, `func get_cell(pos: Vector2i) -> int:`.
6. **Не строим заранее.** Системы из поздних фаз не добавляем, пока до них не дошли. Но оставляем для них одну точку входа.

## Автозагрузки (Autoload, глобальные синглтоны)
| Имя | Файл | Назначение |
|---|---|---|
| `Events` | scripts/autoload/events.gd | Только сигналы (шина событий) |
| `GameState` | scripts/autoload/game_state.gd | Деньги, налог, доход и расходы за день, население, рабочие места, спрос, день, **`grid: CityGrid`** |
| `SaveManager` | scripts/autoload/save_manager.gd | Сохранения: файлы, автосохранение, F5 / F9, новый город |
| `SimClock` | scripts/autoload/sim_clock.gd | Тики симуляции (1 тик = 1 с на ×1 = 1 день), скорость (0/1/3), пауза — Пробел. `set_speed()` — публичный метод, UI зовёт его напрямую |

`GameState` создаёт сетку при старте: `grid = CityGrid.new(GRID_SIZE)`.

## Модель данных

### CityGrid (`class_name CityGrid extends RefCounted`)
- Размер: `GRID_SIZE = 64`, размер клетки в мире: `CELL_SIZE = 2.0` метра.
- Координаты клетки: `Vector2i(x, y)`. В мире: X → ось X, Y → ось Z, высота = 0.
- Слои (по одному значению на клетку, индекс = `y * GRID_SIZE + x`):
  - `tile_type: PackedByteArray` — EMPTY, ROAD, BUILDING
  - `zone: PackedByteArray` — NONE, RESIDENTIAL, COMMERCIAL, INDUSTRIAL
  - `building_at: PackedInt32Array` — номер экземпляра здания на клетке или -1
- Кэши (чтобы не сканировать всю карту):
  - `buildings: Dictionary[int, BuildingInstance]` — все построенные здания
  - `road_cells: Dictionary[Vector2i, bool]` — все клетки с дорогой
  - `next_building_id: int` — счётчик номеров экземпляров
  - `zoned_empty_cells: Dictionary[Zone, Dictionary]` — по зоне R/C/I словарь `Vector2i → true` пустых клеток с этой зоной. Клетка в кэше ⇔ `tile_type == EMPTY и zone != NONE`. Обновляется **только внутри** `CityGrid`: в `set_zone`, `set_road`, `place_building`, `remove_building`. (Godot не умеет вложенные типизированные словари, поэтому внутренний словарь без типа.)
- Обязательные функции:
  - `grid_to_world(cell: Vector2i) -> Vector3`
  - `world_to_grid(pos: Vector3) -> Vector2i`
  - `is_in_bounds(cell: Vector2i) -> bool`
  - `set_road(cell) -> bool` / `remove_road(cell) -> bool` — **единственное** место изменения дорог; увеличивают `roads_version` (по нему пересчитывается `RoadNetwork`). Возвращают `true`, если клетка изменилась. Сигнал не шлют — это делает инструмент пакетом.
  - `place_building(type_id, cell, orientation, clear_zone = false) -> int` — ставит здание на пустую клетку, возвращает номер экземпляра или −1. `clear_zone` — стереть зону (служебные здания). Правила «какой тип на какой зоне» решает вызывающий (`growth.gd`): `CityGrid` не знает про `BuildingData`.
  - `remove_building(instance_id) -> bool` — клетка снова пустая, зона остаётся.
  - `set_zone(cell: Vector2i, zone_type: Zone) -> bool` — **единственное** место изменения зон (фаза 3). Поштучно, как дороги: цикл и один `cells_changed` — в инструменте. `Zone.NONE` снимает зону.
  - `can_zone(cell, zone_type) -> bool` — те же правила без изменения (для превью инструмента).
  - `find_nearest_road_dir(cell) -> int` — направление (0..3 = N/E/S/W) на ближайшую дорогу в радиусе `ROAD_ACCESS_RANGE` (3) по Манхэттену или −1. Ищет кольцами от расстояния 1. Для дороги по диагонали берётся ось с большим смещением.
  - `find_nearest_road(cell) -> Vector2i` — клетка ближайшей дороги или (−1, −1); на ней построены `find_nearest_road_dir` и `has_road_access`.
  - `has_road_access(cell) -> bool` = `find_nearest_road(cell) != (−1, −1)`.
  - `bulldoze(cell) -> bool` — **единственное** место правил сноса: убирает здание или дорогу. Зону **не трогает** — для снятия зоны отдельное действие. Если снести дом, а зону оставить, при спросе на этом месте вырастет новый (как в SimCity).
- Функции добавляются в той фазе, где нужны: фаза 1 — координаты, фаза 2 — дороги, фаза 3 — зоны, фаза 4 — здания.

### BuildingInstance (`class_name BuildingInstance extends RefCounted`)
Один построенный дом.
- `id: int` — уникальный номер экземпляра
- `type_id: StringName` — тип, например `&"res_small_01"` (ссылка на BuildingData.id)
- `cell: Vector2i` — клетка-основание
- `orientation: int` — направление на дорогу 0/1/2/3 = N/E/S/W (поворот по часовой на 0°/90°/180°/270°, как у кусков дорог). Фасад модели в базовом повороте смотрит на N (−Z).
- `no_road_ticks`, `no_power_ticks`, `no_water_ticks: int` — сколько тиков подряд нет дороги / света / воды (состояние симуляции).
- `powered`, `has_water: bool` — результат последнего распределения.

### BuildingData (`class_name BuildingData extends Resource`)
Описание типа здания (файл `.tres`).
- `id: StringName` — уникальный строковый id. **Никогда не меняется после создания** (на нём держатся сохранения).
- `zone`, `population`, `jobs`, `cost`, `upkeep`, `mesh` (пусто — заглушка-коробка из `placeholder_color` и `placeholder_height`)
- Фаза 6: `power_supply`, `water_supply` (даёт), `power_use`, `water_use` (потребляет), `service` (`BuildingData.Service`: NONE, SCHOOL, HEALTH, FIRE, POLICE), `service_radius`.
- Размер: в MVP всегда 1×1.
- Все типы лежат в `data/buildings/*.tres`. `BuildingCatalog` (статический) загружает их при первом обращении через `ResourceLoader.list_directory` (работает и в экспортированной игре). Пустой или повторный `id` — ошибка, такой тип пропускается. Отсортированный список и списки по зонам собираются один раз при загрузке.
- `upkeep` списывается **только у служебных зданий** (`zone = NONE`): дома содержат себя сами.
- `BuildingCatalog.buildable_types()` — служебные здания (`zone = NONE`), для кнопок UI.

### Дороги
Форма (прямая/угол/T/крест) и поворот дороги **не хранятся** — они вычисляются по соседним дорожным клеткам. При загрузке сохранения пересчитываются.
- `CityGrid.get_road_mask(cell) -> int` — 4 бита соседей-дорог: N=1 (−Z), E=2 (+X), S=4 (+Z), W=8 (−X).
- `road_visualizer.gd` (GridMap) по маске выбирает кусок (END, STRAIGHT, CORNER, T, CROSS) и поворот. При `cells_changed` обновляет изменённые клетки **и их соседей**.
- `set_road` на клетке с дорогой или зданием ничего не делает и возвращает `false`; дорога стирает зону клетки.
- Куски дорог в MVP генерируются кодом (`road_meshes.gd`) как заглушки. Позже заменяются на модели (Kenney) без изменения логики: визуализатор зависит только от номеров кусков.

### Зоны
- Зону R/C/I можно поставить только на пустую клетку (не дорога, не здание) **с доступом к дороге**. Снять зону можно с любой пустой клетки.
- Если дорогу снесли, зона остаётся, но теряет доступ: она рисуется тусклее, и на ней ничего не растёт.
- Снять зону под зданием нельзя: сначала снос (B), потом снятие зоны (4). Так не бывает состояния «дом на клетке без зоны».
- Цвет зоны под зданием остаётся (дом его почти закрывает, а цвет показывает, что это за участок).
- `zone_visualizer.gd` — один `MultiMeshInstance3D`, по экземпляру на клетку (номер = `index_of(cell)`), цвет экземпляра = зона. При `cells_changed` перекрашивает клетки в радиусе `ROAD_ACCESS_RANGE` от изменённых (доступ соседей мог измениться): одним общим прямоугольником, или отдельным квадратом вокруг каждой клетки, если так выходит меньше клеток (рост в разных углах карты).
- Цвета: R — зелёный, C — синий, I — жёлтый.

### Симуляция (фаза 4)
Порядок одного тика (`simulation.gd`, узел в главной сцене, подписан на `Events.sim_tick`):
1. **Заброшенные здания.** У каждого здания без доступа к дороге `no_road_ticks += 1`, с доступом — 0. При `no_road_ticks >= ABANDON_TICKS` (3) здание сносится, зона остаётся. Мгновенно при сносе дороги не сносим — чтобы на паузе можно было перестроить перекрёсток.
2. **Рост** (`growth.gd`): для каждой зоны R/C/I со спросом > 0 — одна случайная клетка из `zoned_empty_cells` этой зоны с доступом к дороге; случайный тип здания этой зоны; поворот — `find_nearest_road_dir`.
3. **Подсчёт** населения и рабочих мест C и I по всем зданиям (пересчёт целиком: просто и не расходится).
4. **Спрос** (`demand.gd`), значения в [−1, 1], рост при > 0:
   - R: `(jobs_c + jobs_i + 20 − population) / 50`
   - I: `(0.7 · population + 15 − jobs_i) / 40`
   - C: `(0.3 · population − jobs_c) / 30`
   - К каждому добавляется налоговая поправка `(9 − tax_rate) · 0.08`: налог выше 9 % тормозит рост, ниже — ускоряет.
   - Формулы держат соотношение жители : заводы : магазины ≈ 1 : 0.7 : 0.3. Без налоговой поправки жилой спрос сам вниз не уходит, пока хватает земли всех трёх зон.
5. **Деньги** (`economy.gd`): `money += доход − расходы` (см. «Экономика»).
6. Один `Events.cells_changed` на все изменённые за тик клетки, затем `Events.stats_changed`.

Вне тика (снос на паузе, смена налога, `grid_reset`) `simulation.gd` тоже пересчитывает статистику и спрос и шлёт `stats_changed` — чтобы UI не показывал старые цифры. Флаг «идёт тик» защищает от двойного пересчёта: тик сам шлёт `cells_changed`.

### Экономика (фаза 5)
- **Единственное место изменения денег** — `Economy.spend(amount) -> bool` (строительство) и начисление за день в тике. Остальные только читают `GameState.money`.
- Старт: 2000 $. Цены за **реально изменённую** клетку: дорога 10 $, зона 5 $, снятие зоны и снос — бесплатно (из долга всегда можно выбраться сносом).
- За день: доход `roundi((население + рабочие места C + I) · tax_rate · 0.015)`, расходы `roundi(клетки дорог · 0.2)` + `upkeep` служебных зданий. Дома не платят содержание.
- `GameState.income` / `expenses` — **прогноз на день**, пересчитывается вместе со статистикой (и на паузе: стройка, снос, налог). В тике `Economy.apply_day()` только начисляет `money += income − expenses`.
- Налог: по умолчанию 9 %, от 0 до 20 %, шаг 1 %. UI просит смену через `Events.tax_rate_requested(rate)`, `simulation.gd` проверяет границы и применяет.
- Деньги < 0: игра идёт дальше, сумма в UI красная, банкротства в MVP нет. Платное строительство останавливается там, где кончились деньги; превью заранее показывает только клетки, на которые хватит.
- Все числа — константы в начале `economy.gd`, подбираются игрой.

Числа (`ABANDON_TICKS`, буферы и делители спроса) — константы в начале своих скриптов, подбираются игрой.

### Инструменты (build_tool.gd)
- Режимы: NONE, ROAD, BULLDOZE, ZONE_R, ZONE_C, ZONE_I, DEZONE. Клавиши: R — дорога, B — снос, Esc — выключить.
- Дорога: зажать ЛКМ и тянуть — путь буквой «Г» (сначала по длинной оси). Снос: прямоугольник. ПКМ — отмена протягивания.
- Если мышь ушла за карту во время протягивания, конечная клетка прижимается к краю карты.
- Начало протягивания — в `_unhandled_input` (клик по UI не начнёт стройку). Отпускание ЛКМ и отмена ПКМ — в `_input`, чтобы UI не «съел» их и протягивание не залипло.
- Путь и превью пересчитываются только когда меняется конечная клетка.
- Инструмент меняет клетки только через функции `CityGrid` (`set_road`, `bulldoze`, `set_zone`), сам правил не решает.
- Зоны (фаза 3): 1 — жилая R, 2 — коммерческая C, 3 — промышленная I, 4 — снять зону. Протягивание прямоугольником; превью показывает только клетки, которые реально изменятся (`can_zone`).
- У инструмента `class_name BuildTool`, режим — `BuildTool.Mode`. Кнопки UI переключают режим через `Events.tool_requested(mode)`, инструмент сообщает о любой смене (и от клавиш) через `Events.tool_mode_changed(mode)`.
- Курсор клетки скрывается над UI (`gui_get_hovered_control`), но клетка под мышкой продолжает считаться — начатое протягивание не обрывается, если мышь заехала на панель.
- Платные режимы: перед каждой клеткой — `Economy.can_afford`, после изменения — `Economy.spend`.
- Пока идёт протягивание, превью пересчитывается и по `stats_changed` (деньги могли измениться на тике, пока мышь стоит).
- По `grid_reset` инструмент прерывает протягивание; `SimClock` обнуляет накопленное время.
- При отпускании ЛКМ инструмент меняет все клетки и шлёт **один** `cells_changed`.

### Фаза 6 — электричество, вода, службы
Решения по ревью Argon 005 — в `docs/collab/decisions/005-plan-phase-6.md`.

**Цель:** город без света и воды не растёт; службы (школа, поликлиника, пожарные, полиция) по ступеням населения влияют на желание людей жить в городе. Город сам подсказывает, чего не хватает.

#### Служебные здания
- `BuildingData` с `zone = NONE`: ставятся игроком за `cost`, каждый день списывается `upkeep`. Размер 1×1.
- Стартовый набор: ТЭЦ, водокачка, школа, поликлиника, пожарная часть, полиция (`data/buildings/*.tres`). Числа — в таблице decisions/006 (после правки баланса).
- Постройка: пустая клетка с доступом к дороге и хватает денег → `place_building(..., clear_zone = true)` — зона клетки стирается (после сноса службы на её месте не вырастет дом). Рост домов вызывает с `clear_zone = false`. Фасад к дороге.
- **Служебные здания сами не сносятся.** Без дороги, света или воды они просто не работают (не дают мощность и покрытие). Снос — только игроком (`bulldoze`, бесплатно, без возврата денег).

#### Сеть: свет и вода идут по дорогам
- Отдельных ЛЭП и труб нет. `RoadNetwork` (`scripts/simulation/road_network.gd`) делит `road_cells` на связные компоненты (обход в ширину по 4 соседям). Пересчёт ленивый: `CityGrid.roads_version` растёт в `set_road` / `remove_road`; сеть пересчитывается, только если версия изменилась. Объект лежит в `GameState.network` (его читает слой карты).
- Здание подключено к компоненту **ближайшей** дороги: `CityGrid.find_nearest_road(cell) -> Vector2i` (или (−1, −1)). Здание не соединяет два компонента.
- **Распределение** (`scripts/simulation/utilities.gd`), в каждом компоненте отдельно:
  1. Свет: запас = сумма `power_supply` станций компонента. Потребители получают свет по очереди: сначала служебные здания по `id`, затем дома R/C/I по `id`; кому не хватило — без света (следующим, кому хватает, — дают).
  2. Вода: запас = сумма `water_supply` водокачек компонента **со светом**. Очередь та же.
  3. Здание без `power_use` / `water_use` считается обеспеченным. Здание без дороги — без света и воды.
- Результат: флаги `BuildingInstance.powered` / `has_water`, свободный запас по компонентам (для роста), итоги в `GameState`: `power_supply`, `power_use`, `water_supply`, `water_use`, `unpowered_count`, `no_water_count`, компоненты со светом и водой (для слоя карты).
- Распределение и покрытие служб — **часть пересчёта статистики** (`_update_stats`), а не только тика: на паузе после постройки ТЭЦ или дороги всё обновляется сразу.

#### Последствия
- **Рост:** шанс вырасти дому зоны на тике = `min(1, спрос · 2)`: при спросе ≥ 0.5 — каждый тик, ниже — плавно реже. Кандидат — клетка, у компонента которой свободного света и воды хватает на выбранный тип; после постройки свободный запас сразу уменьшается. Если ни в одном компоненте запаса не хватает — рост сразу выходит, не перебирая клетки. Так налог и службы плавно меняют скорость роста, а не только «растёт / не растёт».
- **Заброшенность (только R/C/I):** без дороги — 3 тика (`ABANDON_TICKS`); без света или воды — 10 тиков (`UTILITY_ABANDON_TICKS`). Счётчики `no_power_ticks`, `no_water_ticks` в `BuildingInstance`. Зона остаётся.
- **Службы** (`scripts/simulation/services.gd`): служба работает, если у здания есть дорога, свет и вода. Покрытие службы = доля жителей, чьи дома в радиусе `service_radius` (по Манхэттену) хотя бы одного работающего здания этой службы.
  - Ступени: школа нужна со 150 жителей, поликлиника — с 250, пожарные — с 350, полиция — с 500.
  - Поправка жилого спроса: `Σ по нужным службам (coverage − 0.5) · 0.25`. Нет службы — −0.125, полное покрытие — +0.125.
- **Деньги:** расходы за день = дороги + `upkeep` всех служебных зданий (и неработающих тоже).

#### Порядок тика (фаза 6)
1. Заброшенные R/C/I — по флагам последнего пересчёта.
2. Рост — с шансом по спросу и проверкой свободного запаса.
3. `_update_stats()`: сеть (если менялись дороги) → свет и вода всем зданиям, включая новые → население и рабочие места → покрытие служб → спрос → прогноз денег.
4. `Economy.apply_day()`.
5. Сигналы: один `cells_changed`, затем `stats_changed`.

#### Инструмент и интерфейс
- Режим `BuildTool.Mode.PLACE` + `type_id`. UI просит через `Events.building_place_requested(type_id)`. Клик ставит здание на клетку под мышкой. Превью — одна клетка: цвет режима или красный, если нельзя (занято, нет дороги, нет денег).
- `Events.tool_mode_changed(mode, type_id)` — чтобы UI подсвечивал и кнопку службы.
- Нижняя панель: кнопки служб из `BuildingCatalog.buildable_types()` (`zone = NONE`), с ценой.
- Верхняя панель: «Свет потребление/запас», «Вода потребление/запас»; красным, если кому-то не хватило.
- **Подсказки** (`scripts/ui/hints.gd`): список строк по `GameState` («Нет света у 12 зданий», «Нужна школа: покрытие 20 %», «Деньги уходят в минус»), панель слева под верхней.
  - Пустой город ведут первые шаги: «Шаг 1: дорога [R]» → «Шаг 2: ТЭЦ и водокачка» → «Шаг 3: зоны [1] и [3]» — станции раньше зон, чтобы не потратить деньги на зоны.
  - Подсказка кнопки служебного здания: цена, содержание, что даёт и что потребляет, радиус и с какого населения нужна служба.
- Постановка здания (`PLACE`) — только там, где виден курсор клетки: отпускание ЛКМ над панелью UI ничего не ставит (в отличие от протягивания дорог и зон).
- На слоях света и воды станция, которая сейчас не работает (нет дороги; водокачка без света), — красная.
- **Слои карты** (клавиша V по кругу, `Events.overlay_changed(mode)`): зоны / свет / вода / службы. Рисует тот же `zone_visualizer.gd` на тех же квадратах клеток. Свет: здания со светом — зелёные, без — красные, дороги с запасом — жёлтые. Вода — так же, синим. Службы — клетки в радиусе работающих служб.
- Значки над домами — отложены.

#### Чего в фазе 6 нет
ЛЭП и трубы отдельно от дорог, пожары и преступность как события, стоимость земли, уровни зданий, здания больше 1×1, значки над домами.

### Фаза 7 — сохранение и загрузка
Решения по ревью Argon 007 — в `docs/collab/decisions/007-plan-phase-7.md`.

**Цель:** сколько угодно сохранённых городов, быстрое сохранение, автосохранение, новый город. Загрузка никогда не портит текущую игру: битый файл — город остаётся как был, игрок видит сообщение.

#### Формат файла
- **JSON** в `user://saves/<файл>.city.json`. Не `store_var` / `.tres`: JSON читается глазами и мигрируется, а `.tres` при загрузке может создать скрипт — чужой файл не должен исполнять код.
- Корень:
  ```
  { "format": "citybuilder-save", "version": 1, "saved_at": "2026-10-25T18:00:00",
    "meta":  { "name": "Мой город", "day": 120, "population": 640, "money": 3150 },
    "state": { "money": 3150, "tax_rate": 9, "day": 120 },
    "grid":  { "size": 64, "next_building_id": 412,
               "roads": "<base64: байт на клетку, 1 — дорога>",
               "zones": "<base64: байт на клетку, CityGrid.Zone>" },
    "buildings": [ { "id": 3, "type": "res_small_01", "x": 10, "y": 18, "o": 2,
                     "nr": 0, "np": 0, "nw": 0 }, ... ] }
  ```
- `meta` — для списка сохранений; имя города живёт внутри файла, имя файла — очищенная версия имени (буквы, цифры, пробел, `_`, `-`; зарезервированные имена Windows получают `_` спереди).
- **Правило совместимости:** незнакомые поля читатель пропускает, отсутствующие берёт по умолчанию. Так позже добавляются размер и стиль здания, уровень, состояние трафика — без поломки старых сохранений.
- `version` новее нашей — отказ; старее — цепочка `_migrate_vN_to_vN1` (в фазе 7 миграций нет, только место).

#### Код
- `scripts/save/city_serializer.gd` (`CitySerializer`, статический, без файлов и сигналов): `to_dict(...)`, `from_dict(data) -> CitySerializer.LoadResult` (`ok`, `error`, `warnings`, `grid`, `money`, `tax_rate`, `day`, `name`). Новый `CityGrid` строится **в стороне**.
  - `JSON.parse_string` отдаёт все числа как `float` — все целые поля явно приводятся к `int`, `type` — к `StringName`.
  - Здания вставляются по возрастанию `id` (на этом порядке держится раздача света и воды); `next_building_id = max(сохранённый, max(id) + 1)`.
- `CityGrid.rebuild_caches()` — из слоёв и `buildings` пересобирает `road_cells`, `tile_type = BUILDING`, `building_at`, `zoned_empty_cells`, `next_building_id`; `roads_version += 1`.
- `scripts/autoload/save_manager.gd` — **четвёртая автозагрузка `SaveManager`**: `save_city(name)`, `load_city(file_id)`, `new_city()`, `list_saves()`, `delete_save(file_id)`; UI зовёт их напрямую, как `SimClock.set_speed`. Папка — `save_dir` (переменная, тесты пишут в свою).
- Загрузка: файл → JSON → `from_dict` → если `ok`: заменить `GameState.grid`, деньги, налог, день, имя → `Events.grid_reset`. Иначе ничего не трогаем → `Events.save_error(message)`.
- **Запись:** `<файл>.tmp`, затем `DirAccess.rename_absolute` поверх старого (в Godot 4.7 на Windows перезаписывает — проверено).
- `Simulation` стоит в сцене **выше** визуализаторов: по `grid_reset` она пересчитывает сеть, свет и воду раньше, чем визуализаторы перерисуются.

#### Проверки при загрузке
- **Отказ:** не JSON, чужой `format`, `version` новее нашей, `size` вне 16..256, длина слоёв ≠ `size²`, байт зоны вне `CityGrid.Zone`, байт дороги не 0/1.
- **Предупреждение и пропуск здания:** неизвестный тип, вне карты, на дороге, второе на клетке, повтор `id`, `orientation` вне 0..3. Зона на клетке дороги и под служебным зданием стирается (как при обычной постройке); `rebuild_caches` тоже снимает зону с клеток дорог.

#### Новый город, автосохранение, клавиши
- `new_city()`: новый `CityGrid`, стартовые деньги, налог по умолчанию, день 0, имя «Новый город» → `grid_reset`. Перед этим окно «Сохранить текущий город?».
- Автосохранение в `autosave` через каждые 30 игровых дней **от последнего автосохранения** (загрузка и новый город сбрасывают отсчёт — иначе после загрузки сохранения с дня 30 оно сработало бы сразу) и при закрытии окна — **только если город не пустой** (есть дороги или здания), чтобы не затереть прошлое автосохранение пустой картой.
- В списке сохранений автосохранение и быстрое сохранение помечены («Автосохранение: Мой город»), битый файл — «(повреждено)».
- F5 — быстрое сохранение (`quicksave`), F9 — быстрая загрузка.
- Сообщения в HUD на 2–3 с: `Events.save_done(name)`, `load_done(name, warnings)`, `save_error(message)`.

#### Интерфейс
- В верхней панели: «Города» (окно сохранений) и «Новый город».
- Окно сохранений: список (имя, день, жители, деньги, дата), поле имени, «Сохранить», «Загрузить» (и двойной клик), «Удалить» с подтверждением, «Закрыть». Пока окно открыто — пауза и инструмент выключен; клики в мир не проходят.
- Камера не двигается, пока фокус в поле ввода или открыто окно поверх игры (`RTSCamera` опрашивает клавиши каждый кадр напрямую и узнаёт об окнах по `Events.modal_changed`). Окно подтверждения «Новый город» тоже ставит паузу. По `grid_reset` камера прижимается к границам новой карты.
- Esc закрывает окно сохранений с первого нажатия (ловится в `_input`, до поля ввода).
- Имя файла сравнивается со служебными (`autosave`, `quicksave`) и зарезервированными именами Windows **без учёта регистра** (файловая система Windows регистр не различает). `_path` берёт только имя файла (`get_file()`) — выйти за `save_dir` нельзя.
- На слоях карты (V) перерисовка пропускается, пока число экземпляров MultiMesh не совпадает с новой картой: по `grid_reset` `stats_changed` приходит раньше, чем визуализатор пересобран.

#### Чего в фазе 7 нет
Положение камеры в сохранении, сид случайности, ротация автосохранений, сжатие, облачные сохранения, превью-скриншот города.

### Фаза 8 — трафик (ПЛАН, на ревью Argon 009)
Черновик. После ревью решения переносятся в разделы выше, а этот раздел заменяется итоговым.

**Цель:** жители ездят из дома на работу по дорогам; где поездок больше, чем дорога выдерживает, — пробка. Длинная или забитая дорога до работы делает город менее привлекательным для жизни. Машинки на дорогах — для живости (как в ориентире CityRT), на симуляцию не влияют.

#### Модель: потоки, а не отдельные машины
- Симуляция считает **поездки целиком**, без агентов: каждый дом R отправляет `workers = population · WORK_SHARE` (0.5) человек к **ближайшему по времени пути** месту работы (здания C и I).
- **Один проход на компонент** вместо поиска пути от каждого дома: многоисточниковый Дейкстра по клеткам дорог **от всех мест работы сразу**. Для каждой клетки дороги получаем время до ближайшей работы и «следующую клетку» к ней. Путь дома — по этим указателям от его ближайшей дороги (`find_nearest_road`). Сложность — O(дороги · log + сумма длин путей), а не O(дома · дороги).
- Почему не `AStarGrid2D`: он ищет путь между одной парой точек; нам нужны пути всех домов к ближайшей работе — многоисточниковый проход дешевле в разы. `AStarGrid2D` в фазе 8 не нужен.
- Свободность рабочих мест не учитывается (едут к ближайшей работе, даже если она «переполнена») — упрощение MVP трафика.
- **Нагрузка клетки** = сумма работников, чьи пути через неё проходят. `CAPACITY = 40` на клетку (один тип дороги). Загрузка = нагрузка / ёмкость.
- **Стоимость клетки** в Дейкстре = `1 + JAM_PENALTY · max(0, загрузка − 1)` по загрузке **прошлого расчёта** (2.0) — водители объезжают пробки, если есть объезд; без объезда пробка остаётся.
- Расчёт — `scripts/simulation/traffic.gd` (`class_name Traffic`, статический, как `Utilities`): `compute(grid, network, previous) -> Traffic` с полями `load: PackedInt32Array` (по индексу клетки), `commute_time` по домам, итоги (`average_commute`, `long_commute_share`, `jammed_cells`), выборка путей для машинок. Результат — в `GameState.traffic`.
- Пересчёт **не на каждом тике**: раз в `TRAFFIC_PERIOD` (5) тиков и сразу, если изменились дороги (`roads_version`) — иначе по старым путям ездили бы через снесённую дорогу. На паузе после стройки дороги — тоже сразу.

#### Последствия
- **Время до работы** дома = сумма стоимостей клеток пути (+ расстояние до дороги). `OK_COMMUTE = 20`, `MAX_COMMUTE = 60`.
- **Жилой спрос:** `− TRAFFIC_WEIGHT · (доля работников с временем > OK_COMMUTE)` (0.3). Нет работы в компоненте вовсе — тоже считается «далеко».
- Заброшенности из-за трафика в фазе 8 нет — только спрос (мягкий рычаг, как службы).
- **Деньги:** без изменений (ёмкость дорог не покупается — один тип дороги).

#### Порядок тика (фаза 8)
Как в фазе 6, в `_update_stats()` после распределения света и воды и подсчёта жителей: → **трафик (если пора)** → покрытие служб → спрос (с поправкой трафика) → прогноз денег.

#### Отображение
- **Слой карты «Трафик»** (пятый по клавише V): клетки дорог от зелёного (свободно) через жёлтый к красному (загрузка ≥ 1).
- **Машинки** (`scripts/grid/traffic_visualizer.gd`, `MultiMeshInstance3D`, коробочки): число ∝ поездкам, не больше `MAX_CARS` (300). Каждая едет по одному из путей выборки от дома к работе и обратно, по полосе справа, медленнее на загруженных клетках. Только визуал: ничего не меняет в симуляции и не сохраняется.
- **HUD:** «Пробки: N клеток», среднее время до работы; подсказка «Жителям далеко до работы: N %», «Пробки: постройте объезд».

#### Сохранение
Ничего нового: нагрузка и пути — вторичное состояние, пересчитываются после `grid_reset`. Формат не меняется.

#### Чего в фазе 8 нет
Типы дорог (проспекты, шоссе) и их ёмкость, общественный транспорт, поездки в магазины, грузовики промзон, светофоры, ДТП, заброшенность из-за пробок, учёт свободных рабочих мест.

## Сигналы (Events)
- `cells_changed(cells: Array[Vector2i])` — пакетный. Инструмент сначала меняет все клетки, затем шлёт **один** сигнал на всю операцию.
- `grid_reset()` — сетка полностью заменена (загрузка/новая игра), визуал перестраивается целиком.
- `sim_tick()` — шлёт `SimClock`, один раз за тик симуляции.
- `stats_changed()` — шлёт `simulation.gd` после тика и после изменений вне тика: в `GameState` обновлены деньги, население, рабочие места, спрос.
- `tool_requested(mode: int)` — UI просит сменить инструмент.
- `tool_mode_changed(mode: int, type_id: StringName)` — инструмент сменил режим (от кнопки или клавиши); `type_id` — для режима PLACE.
- `building_place_requested(type_id: StringName)` — UI просит режим постановки служебного здания.
- `overlay_changed(mode: int)` — сменился слой карты (V).
- `save_done(name: String)`, `load_done(name: String, warnings: int)`, `save_error(message: String)` — для сообщений в HUD.
- `modal_changed(open: bool)` — открылось или закрылось окно поверх игры (камера перестаёт слушать клавиши).
- `speed_changed(speed: int)` — шлёт `SimClock.set_speed`.
- `tax_rate_requested(rate: int)` — UI просит сменить налог.

### Интерфейс (`scenes/ui/hud.tscn`, `hud.gd`)
- `CanvasLayer` → корневой `Control` на весь экран с `mouse_filter = IGNORE` (клики мимо панелей идут в мир).
- Верхняя панель: деньги и баланс за день (подсказка: доход и содержание отдельно), день, жители, рабочие места, спрос R/C/I, налог (−/+, кнопки гаснут на границах), скорость (Пауза / ×1 / ×3).
- Полоска спроса (`demand_bar.gd`) растёт **от центра**: вправо цветом зоны при спросе > 0, влево тусклым при < 0, посередине риска нуля. Пустая полоска = рост стоит.
- Нижняя панель: кнопки инструментов с клавишей и ценой. Кнопки создаются кодом из таблицы режимов.
- У всех кнопок `focus_mode = NONE`: иначе Пробел нажимал бы последнюю нажатую кнопку вместо паузы.
- UI не меняет состояние напрямую: только сигналы `Events` и `SimClock.set_speed`.
- Остальные сигналы добавляются сюда по мере появления.

## Отображение
- Дороги и здания: `GridMap` + `MeshLibrary` (в 4.7 есть встроенный редактор MeshLibrary). MeshLibrary зданий собирается кодом из `BuildingCatalog` (номер куска = порядок типов по `id`).
- Если зданий станет очень много — переход на `MultiMeshInstance3D`.
- Зоны: полупрозрачная раскраска клеток.

## Отложенные решения
- Поиск пути (фазы 6, 8): `AStarGrid2D` или обход в ширину по `road_cells` — добавляется в `set_road/remove_road`.
- Здания больше 1×1: экземпляр уже хранит основание, добавится поле размера.
- **Загрузка сохранений (фаза 7):** не через `set_zone`/`set_road` — в сохранении бывают зоны без доступа к дороге и зоны под домами. Загрузка пишет слои и здания напрямую, затем `CityGrid.rebuild_caches()` пересобирает `road_cells`, `zoned_empty_cells`, `buildings`/`building_at`, `next_building_id`; затем `grid_reset`.
  - **Сохраняется:** `GameState.money`, `tax_rate`, `day`; `CityGrid.size`, дороги, слой `zone`, `next_building_id`; здания: `id`, `type_id`, `cell`, `orientation`, `no_road_ticks`, `no_power_ticks`, `no_water_ticks`.
  - **Не сохраняется (пересчитывается):** `roads_version`, кэши `CityGrid`, `powered` / `has_water`, `GameState.network`, `utilities`, `service_coverage`, население, рабочие места, спрос, доход и расходы — всё это даёт `grid_reset` → `Simulation._refresh_stats()`.
- **Поиск пути (фаза 8):** компоненты уже есть в `RoadNetwork`; `AStarGrid2D` будет обновляться там же по `roads_version`.

## Соглашения
- Файлы и переменные: `snake_case`. Классы: `PascalCase` (`class_name CityGrid`).
