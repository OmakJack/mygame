# Пак городских служб и ветрогенераторов с анимацией (Blender 5.2)

Готовый набор low-poly 3D-моделей для городских служб (**полицейский участок, пожарное депо, поликлиника** — каждая в двух размерах: `1×1` и `2×1`) и зелёной энергетики (**трёхлопастной ветряк HAWT** и **вертикально-осевой ветрогенератор VAWT** на участках `1×1` **с glTF-анимацией вращения**).

Модели пока **не подключены в код игры** — они полностью подготовлены под конвенции проекта (`ModelLoader`, `BuildingPalette`, `ConstructionVisualizer`, `generate_building_types.gd`) и вынесены в отдельную папку `assets/models/blender/services/` (чтобы не попадать в `pack/manifest.json`, откуда генератор берёт растущие по зонам дома).

  - `wind_turbine_vawt_1x1.glb` — вертикально-осевой спиральный ветрогенератор (Дарье–Горлова) с зацикленной анимацией `"spin-loop"`

- `assets/models/blender/services/manifest.json` — машиночитаемый реестр всех моделей, габаритов, треугольников, узлов и точных координат осей вращения

## Технические параметры для интеграции в Godot (памятка для Claude)

1. **Масштаб и сетка (`model_scale = 1.0`, `CityGrid.CELL_SIZE = 2.0` м):**
   - Центр участка `(0, 0)`, подошва всех моделей строго на высоте `0.0`.
   - Модели `1×1` имеют базу `1.74 × 1.74` м (`<= 1.80` м — `ModelLoader.fitted_rect` оставляет чистый масштаб `1.0` и нулевой сдвиг `bottom_center = (0, 0, 0)`).
   - Модели `2×1` имеют габариты `3.62..3.74 × 1.76..1.78` м (под `size = Vector2i(2, 1)`).
   - Почему даны оба размера (`1×1` и `2×1`): `1×1` можно сразу подставить в существующие `police_01`, `fire_01`, `health_01` без поломки старых сохранений, а `2×1` использовать как крупные станции/управления (`police_02`, `fire_02`, `health_02`) — `BuildTool` (`Mode.PLACE`) уже поддерживает многоклеточный `data.size`.

2. **Ориентация фасада (`model_turns = 2`):**
   - В Blender главный фасад (выездные ворота, портик, навес скорой, гондола ветряка) смотрит на **`-Y`**.
   - В Godot при **`model_turns = 2`** (поворот на `180°` вокруг `Y`) фасад встаёт к улице на **`-Z`**, как у всех остальных моделей из `tools/blender/`.

3. **Пути в `tools/generate_building_types.gd`:**
   - `_model_path(relative)` уже переводит любой путь с префиксом `"blender/"` в `"res://assets/models/" + relative + ".glb"`.
   - Готовые значения лежат в поле `godot_kit_path` в `manifest.json` (например, `"blender/services/police_station_1x1"`, `"blender/services/wind_turbine_hawt_1x1"`).

4. **Палитра `colormap.png`, точные цвета служб и вывески:**
   - Все модели используют один материал на `res://assets/models/kenney/suburban/Textures/colormap.png` с плавными АО-градиентами и безопасными отступами UV от границ ячеек.
   - В `BuildingPalette.custom_for` для всех зданий с `data.zone == CityGrid.Zone.NONE` возвращается `Color(0, 0, 0, 0)` (`custom.a = 0`), поэтому службы и электростанции **не перекрашиваются случайно по районам** — синие полосы и золотой щит полиции, красные ворота пожарного депо, красные кресты поликлиники и зелёные эко-полосы ветряков отображаются в своих точных цветах и при этом на 100 % совместимы с `BuildingPalette.convert` и шейдером разреза стройки `ConstructionVisualizer`.
   - Рекомендуется ставить **`sign_color = Color(0, 0, 0, 0)`**, так как объёмные 3D-эмблемы (золотая звезда-щит полиции, мальтийский крест пожарных, красные кресты медицины) и спецтранспорт уже встроены в геометрию каждого здания.

## Как подключить анимацию вращения ветрогенераторов (2 способа на выбор)

Оба ветряка проверены на отсутствие пересечения лопастей между соседними клетками ветропарка (`R = 0.98` м у HAWT → диаметр `1.96 < 2.00` м клетки; у VAWT радиус ротора `0.58` м).

### Вариант А — Сцена `.glb` + `AnimationPlayer` (самый простой, из коробки)
В `wind_turbine_hawt_1x1.glb` и `wind_turbine_vawt_1x1.glb` записана иерархия `Base` → дочерний `Rotor` и линейная анимация **`"spin-loop"`**:
- `wind_turbine_hawt_1x1.glb`: `120` кадров при `30 FPS` (`4.0` с на полный оборот `360°` вокруг оси вала гондолы).
- `wind_turbine_vawt_1x1.glb`: `90` кадров при `30 FPS` (`3.0` с на полный оборот `360°` вокруг вертикальной оси).
- Благодаря суффиксу **`-loop`** импортёр glTF в Godot 4 **автоматически** выставляет клипу режим `Animation.LOOP_LINEAR`.
- При инстанцировании сцены на клетку достаточно повернуть корень с учётом `model_turns = 2`:
  ```gdscript
  var node: Node3D = scene.instantiate()
  node.transform = Transform3D(
      Basis(Vector3.UP, -(building.orientation + 2) * PI * 0.5),
      grid.footprint_center(building.cell, building.size)
  )
  var anim: AnimationPlayer = node.get_node("AnimationPlayer")
  anim.play("spin-loop")
  anim.speed_scale = float(SimClock.speed) # 0 на паузе, быстрее на ×3 / ×8
  ```

### Вариант Б — Через `MultiMeshInstance3D` (как `ConstructionVisualizer`, 2 draw call на весь ветропарк)
Если хочется оставить все статичные башни в общем `BuildingVisualizer` и рендерить сотни ветряков за 2 вызова отрисовки:
1. В `BuildingData.model` указать статичную часть:
   - `"blender/services/parts/wind_hawt_base"` (фундамент, коническая мачта, шкаф автоматики и гондола — сразу работает и со стройплощадкой `ConstructionVisualizer`!)
   - `"blender/services/parts/wind_vawt_base"` (основание, статор генератора с рёбрами охлаждения и солнечный инвертор)
2. Ротор загрузить без сдвига центра через `ModelLoader.merge` с поворотом `turns = 2` (`Basis(Vector3.UP, -PI)`), чтобы локальный `(0, 0, 0)` остался точно на оси вращения:
   ```gdscript
   var turn2 := Transform3D(Basis(Vector3.UP, -PI), Vector3.ZERO)
   var hawt_rotor_mesh: ArrayMesh = BuildingPalette.convert(ModelLoader.merge(load("res://assets/models/blender/services/parts/wind_hawt_rotor.glb"), turn2))
   var vawt_rotor_mesh: ArrayMesh = BuildingPalette.convert(ModelLoader.merge(load("res://assets/models/blender/services/parts/wind_vawt_rotor.glb"), turn2))
   ```
3. В лёгком визуализаторе на каждый кадр собирать трансформ экземпляра ротора (`construction_ticks == 0`):
   - **Трёхлопастной ветряк (`HAWT`):** точка подвеса ротора (относительно центра клетки при `turns = 2`) — **`Vector3(0.0, 3.38, -0.44)`**, ось вращения — локальная **`Vector3.BACK` (`Z`)**:
     ```gdscript
     var b_basis := Basis(Vector3.UP, -building.orientation * PI * 0.5)
     var hub_pos: Vector3 = center + b_basis * Vector3(0.0, 3.38, -0.44)
     var spin := Basis(Vector3.BACK, phase_angle)
     multimesh.set_instance_transform(i, Transform3D(b_basis * spin, hub_pos))
     ```
   - **Вертикально-осевой ветрогенератор (`VAWT`):** точка подвеса ротора — **`Vector3(0.0, 1.04, 0.0)`**, ось вращения — вертикальная **`Vector3.UP` (`Y`)**:
     ```gdscript
     var b_basis := Basis(Vector3.UP, -building.orientation * PI * 0.5)
     var hub_pos: Vector3 = center + Vector3(0.0, 1.04, 0.0)
     var spin := Basis(Vector3.UP, phase_angle)
     multimesh.set_instance_transform(i, Transform3D(b_basis * spin, hub_pos))
     ```
   *(Небольшой сдвиг начальной фазы `building.id * 1.7` сделает вращение соседних ветряков живым и несинхронным.)*
